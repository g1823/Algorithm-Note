# 1049. 最后一块石头的重量 II

## 1. 解题思路

**题目**：有一堆石头，每块重量 `stones[i]`。每次任选两块石头相撞（大减小的绝对值，相等则同归于尽），直到只剩一块。求这一块石头**可能的最小重量**。

**核心难点**：识别出"碰撞过程"与"双方对抗"无关，本质是**把石头分成两堆，求两堆重量差的最小值**。

**第一步：碰撞 = 给每块石头分配 ± 号**

任取两块 a、b 相撞得到 |a−b|，再与 c 相撞得到 `| |a−b| − c |`，剥开绝对值后形如 `|a − b − c|` 或 `|b − a − c|` 等。可归纳证明：**无论按什么顺序、怎么撞，最终结果都能写成所有石头带正负号求和再取绝对值 `|Σ ±w_i|`，且每块原始石头恰好出现一次**（系数恒为 ±1）。绝对值嵌套再多层，也只是让每块石头被套上 + 或 −，不会重复计入。

因此问题与"博弈""轮流选择"无关 → 等价于把石头分成 **A、B 两堆**，答案 = `|sum(A) − sum(B)|` 的最小值。

**第二步：化归为"最接近一半"的子集和**

设总和为 sum，A 堆和为 a（把较重的一堆命名为 B，可保证 `a ≤ sum/2`）：

- B 堆和 = `sum − a`
- 两堆差 = `(sum − a) − a = sum − 2a`

要让差值最小，只需让 a 在不超过 `sum/2` 的前提下**尽量大**。即：

> 选出若干石头，使其总重量是 **≤ sum/2 的最大可凑出值 j**，答案 = `sum − 2j`。

这就是 **0-1 背包**问题（每块石头选进 A 堆 / 不进 A 堆，每块恰用一次），容量取 `floor(sum/2)`。

**第三步：状态设计与转移**

- `dp[j]`：布尔值，表示**能否凑出重量 j**（可行性，而非方案数——这是与 494 目标和的本质区别）。
- 初始化 `dp[0] = true`（空集凑出 0）。
- 遍历每块石头 w，**倒序**更新（0-1 背包防同一块被重复使用）：
  - `dp[j] = dp[j]`（不取 w）`|| dp[j − w]`（取 w）
  - 倒序只须到 `j >= w`（`j < w` 时装不下，状态不变）。
- 填完后从 `sum/2` 往下找**第一个**为 true 的下标 j，即为最接近一半的可凑重量。

**时间复杂度**：O(n × sum/2) = O(n·sum)；**空间复杂度**：O(sum/2) = O(sum)。

> 注：`n ≤ 30`、`stones[i] ≤ 100`，故 `sum ≤ 3000`，O(n·sum) ≈ 9 万，完全可行——这是 0-1 背包"伪多项式"复杂度在数据范围受限时可用的典型场景。

## 2. 代码实现

```java
public class LastStoneWeightII {

    /**
     * 最后一块石头的重量 II —— 0-1 背包（布尔可行性）
     * 思路：碰撞等价于给每块石头分配正负号 → 分成两堆求差最小 → 找 ≤ sum/2 的最大可凑重量 j，答案 = sum - 2j
     */
    public int lastStoneWeightII(int[] stones) {
        int sum = 0;
        for (int stone : stones) {
            sum += stone;
        }
        // dp[j]: 能否凑出重量 j；容量只开到 sum/2（向下取整即可，无需奇偶判断）
        boolean[] dp = new boolean[sum / 2 + 1];
        dp[0] = true;   // 空集凑出 0
        for (int stone : stones) {
            // 0-1 背包必须倒序，避免同一块石头被重复使用；
            // 下界取 i >= stone：装不下时 dp[i] 状态不变，无需处理，同时避免数组越界
            for (int i = dp.length - 1; i >= stone; i--) {
                dp[i] = dp[i] || dp[i - stone];   // 不取 || 取当前石头
            }
        }
        // 从最接近一半处往下找第一个可凑出的重量
        for (int i = dp.length - 1; i > 0; i--) {
            if (dp[i]) {
                return sum - 2 * i;   // 两堆差 = (sum - i) - i
            }
        }
        // 只有一块石头（或装不进任何石头）时 A 堆为空，j = 0，答案为 sum
        return sum;
    }
}
```

## 3. 踩坑记录

- **内层循环下界写错导致数组越界**：最初写 `for (i = dp.length-1; i > 0; i--)`，当 `i < stone` 时 `dp[i - stone]` 下标为负。必须写成 `i >= stone`（i 小于 stone 表示装不下当前石头，dp[i] 本来就不变）。
- **兜底返回值错写为 0**：若最大石头超过 `sum/2`（如只有一块 `[100]`，容量仅 50），任何石头都塞不进背包，最优解是 A 堆为空（j = 0），答案应为 **sum**（100）而非 0。兜底需对应 j = 0。
- **不必判奇偶**：直接令容量 = `sum/2`（向下取整）即可，答案用 `sum - 2*j` 一步得出，不要绕道 `(sum/2 - j) * 2`，避免被取整干扰。

## 4. 技巧总结

- **问题转化**：碰撞/抵消类操作，若运算可交换、可归纳为线性组合，常可转化为"分配正负号"或"划分子集"问题（详见 [背包应用](../经典解法/03-动态规划/背包应用.md)）。
- **最接近型背包**：目标不是"恰好凑出 target"而是"≤ target 的最大值"时，用**布尔 dp** 记录可行性，最后**倒序扫描**第一个 true 即可，比计数型更省（int → boolean）也更直接。
- **0-1 背包压缩为一维后必须倒序遍历**，且遍历下界可裁剪到 `>= w` 以同时防越界与提速。

### 与 416 / 494 的对照（背包三兄弟）

三者统一模型都是"给每个数分配进/不进某一集合（± 号）"，区别只在目标：

| 题目 | 问题 | dp 存什么 | 结论读取方式 |
|------|------|-----------|--------------|
| 416. 分割等和子集 | 能否**恰好**分成和相等的两半 | boolean | 判 `dp[sum/2]`，sum 为奇直接 false |
| 494. 目标和 | ± 号后和**恰好**等于 target 的**方案数** | int 计数 | 返回 `dp[(sum+target)/2]` |
| 1049. 最后一块石头的重量 II | ± 号后绝对值**尽量小** | boolean | 倒序扫第一个 true，`sum - 2j` |

## 5. 思考过程（agent 对话学习）

本题的价值不在于背包写法本身，而在于两次**认知反转**，按时间线记录如下：

1. **最初误判为博弈问题**：认为两堆石头"轮流对撞、都想让最终差异对自己有利"，于是往"双方最优策略"方向想，还举出"先手选最大、第四大，对手选第二、第三大来缩小差距"的例子来论证博弈不成立——但论证完只是否定了博弈，并没有给出真正的模型。
2. **关键一问**：引导思考"无论怎么撞，最终那块石头能否写成某种统一形式"。由此意识到**碰撞只是减法**，连续嵌套的减法剥开绝对值后，每块石头恰好贡献一个 ±1 系数，与顺序、与"谁控制"完全无关。于是问题从"对抗"翻转为"我自己把石头分成两堆"。**第一次反转：博弈题其实是划分题。**
3. **联想到 494 目标和**：方向对了但表述粗糙——以为只是"target = 0 且不需要严格等于"。被追问精确化后才推导出 `sum − 2a` 的最小化等价于"a 尽量接近 sum/2 且不超过它"，目标从"凑数字"收敛为"找最接近一半的可凑重量"。
4. **第二处反复出现的误区**："抵消剩余的石头还会继续参与后续抵消 → 每块石头其实能多次使用，所以没有数量限制"。这是**理解反了**。代数展开证明剩余石头继续撞只是给差值继续套 ± 号，每块原始石头的系数永远是 ±1、恰好一次。所谓"无数量限制"指的是 **A 堆可装任意多块，约束只在重量和上**，而这正是 0-1 背包"每件物品选/不选"恰好需要的性质。**第二次反转：碰撞的"连续"恰恰保证了每块石头只算一次。**
5. **落地 DP**：自己写出"外层遍历物品（前 i 块状态）、内层倒序防重复、一维布尔数组、`dp[j] = dp[j] || dp[j−w]`"的转移，与 494 共用同一套滚动数组心智模型；最终由代码实际运行暴露并修复了两个坑（下界越界、兜底返回值），让抽象理解落到了可运行的正确代码上。

**核心收获**：一道题先要找到"操作的不变量"（这里每块石头 ±1 恰好一次），模型才能稳定；而把新题套进旧模型（494/416）时，必须明确新旧差异在**计数 vs 可行性**、**精确 vs 最接近**，而不是生搬硬套。
