# 石子游戏 [877]

## 1. 解题思路

**问题**：给定偶数堆石子排成一行，`piles[i]` 为每堆石子数。Alice 先手，两人轮流从数组**最左端或最右端**取走一整堆，取完为止，石子总数多者获胜。双方都采取最优策略，判断 Alice 是否必胜。

**核心难点**：两人轮流从两端取数，看似必须用区间 DP（如 486 预测赢家）才能判断胜负。

**关键发现：题目给定了两个特殊约束**

1. 堆数为**偶数**
2. 石子总数是**奇数**（保证无平局，两组和必不相等）

**核心思想：奇偶分组 + 主动选择**

把一堆石子按下标分成两组：

- 偶数下标组：`piles[0], piles[2], piles[4]...`
- 奇数下标组：`piles[1], piles[3], piles[5]...`

由于堆数为偶数，两组**堆数相等**（各 n/2 堆）。

**Alice 可以主动锁定其中一组**：

- 第一步取 `piles[0]`（偶数下标）→ 剩下区间 `[1, n-1]` 两端都是奇数下标，Bob 被迫只能取奇数下标的堆；
- 第一步取 `piles[n-1]`（奇数下标）→ 剩下区间 `[0, n-2]` 两端都是偶数下标，Bob 被迫只能取偶数下标的堆。

无论 Bob 怎么取，只要 Alice 每次取完都让区间两端重新变成"奇数+奇数"（或"偶数+偶数"），她就能**全程只取某一组**，Bob 永远只能从另一组里取，无法破坏。

**结论**：既然总数为奇数，奇数组与偶数组的总和**必不相等**。Alice 只需在第一步选择**总和更大**的那一组，就能保证自己拿到的石子总数一定多于 Bob → **Alice 必胜** → 直接返回 `true`。

> 这是典型的"证明存在必胜策略"：不需要证明 Alice 所有取法都能赢，只要存在一个可控的必胜策略即可。

**时间/空间复杂度**：O(1)，连数组都不用遍历。

## 2. 代码实现

```java
package leetCode.moderately;

/**
 * @description: 877. 石子游戏
 *
 * 思路：堆数为偶数、总数为奇数。
 * 按下标奇偶分组，两组堆数相等且总和必不相等。
 * Alice 第一步即可主动选择总和更大的一组并全程只取该组，Bob 无法阻止。
 * 因此 Alice 必胜，直接返回 true。
 */
public class StoneGame {
    public boolean stoneGame(int[] piles) {
        return true;
    }
}
```

**对比：486 预测赢家的通用 DP 解法**

若去掉"偶数堆、奇数总数"的约束（即 486 的通用情况），才需要博弈 DP：

```java
// dp[l][r] = max(piles[l] - dp[l+1][r], piles[r] - dp[l][r-1])
// dp[l][r] 表示区间 [l, r] 内当前玩家相对对手最多领先的分数
public boolean stoneGame(int[] piles) {
    int n = piles.length;
    int[][] dp = new int[n][n];
    for (int i = 0; i < n; i++) dp[i][i] = piles[i];
    for (int len = 1; len < n; len++) {
        for (int l = 0; l + len < n; l++) {
            int r = l + len;
            dp[l][r] = Math.max(
                piles[l] - dp[l + 1][r],
                piles[r] - dp[l][r - 1]
            );
        }
    }
    return dp[0][n - 1] >= 0;   // 先手净胜分 >= 0 即至少不败
}
```

877 正是 486 的一个**特殊约束下的退化版本**：约束保证先手必胜，DP 退化为直接返回 `true`。

## 3. 踩坑记录

- **不要误以为必须 DP**：看到"两端取数 + 双方最优"，惯性会直接上区间 DP。但 877 的偶数堆 + 奇数总数约束已经决定了先手必胜，O(1) 即可解决，DP 反而掩盖了本质。
- **"存在性"与"唯一性"区分**：Alice 混着取（部分奇数部分偶数）在某些局面下也能赢，但证明必胜只需要**存在一个可控策略**即可，不必保证所有策略都必胜。
- **控制权在 Alice 手里**：取哪一组是 Alice 第一步主动选择的，不是被迫的；Bob 无论怎么取都无法打断"全程只取一组"这个策略。

## 4. 技巧总结

- **奇偶分组 + 主动选择**：当玩家能通过第一步选择锁定一组下标（两两配对、对称取法）时，博弈往往可以数学化简，无需 DP。类似思想见 [博弈DP(零和博弈)](../经典解法/动态规划DP/博弈DP(零和博弈).md) 第 6 节的"奇偶性/对称性剪枝"。
- **约束即捷径**：题干中"偶数堆、奇数总数"这类看似无关的约束，往往是给出简化路径的信号，先审视约束再决定是否上重型算法。
- **与 486 预测赢家对比**：486 是通用区间博弈 DP 原型；877 是它的约束特例。二者对比理解，能同时吃透"通用 DP"与"特例化简"两种视角。

## 5. 思考过程

本次学习基于与 agent 的对话完成，记录认知转变过程：

1. **最初困惑**：没看懂题目要求，尤其是"两人都最优"下的必胜判断，直觉认为必须用博弈 DP。
2. **发现与 486 的同构**：意识到 877 与 486 预测赢家几乎一模一样，只是多了"偶数堆、奇数总数"两个约束。这是第一个认知突破——它不是新题型，而是已知题型的特例。
3. **追问混合取法的疑惑**：曾怀疑"Alice 能否混着取（部分奇数部分偶数）也能赢"，被引导后意识到证明必胜只需**存在**一个可控策略，不需要保证所有策略必胜——这是从"找最优解"到"证明存在性"的思维转变。
4. **奇偶分组的顿悟**：通过"第一步取 piles[0] 或 piles[n-1] 即可锁定一组"这一关键点，明白了 Bob 完全无法破坏这个策略。
5. **最终闭环**：总数为奇数 → 两组和必不相等 → 选大的一组 → 必胜 → 直接返回 `true`。整个推理从"需要 DP"退化到"O(1) 结论"，非常 elegant。
