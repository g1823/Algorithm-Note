# 得分最高的最小轮调[798]

## 1. 解题思路

### 问题分析

给定数组 `nums`（长度 `n`），对它进行轮调：轮调 `k` 次后，原下标 `i` 的元素移动到新下标 `(i-k) mod n`（向左轮调）。元素 `nums[i]` 得分的条件是：**轮调后的新下标 ≥ 元素值**，即 `nums[i] <= (i-k) mod n`。

求：使得分最大的**最小** `k`（`0 ≤ k < n`）。

> 注意这里的 `mod` 是数学取模，结果在 `[0, n-1]`，详见踩坑记录。

### 解法一：暴力枚举（O(n²)，超时）

枚举每个 `k`，再遍历所有元素判断是否得分，统计得分取最大。时间复杂度 O(n²)，`n` 最大 2×10⁵，必然超时。但**作为正确性验证基准很有价值**，后续差分解法可以通过对拍验证。

### 解法二：差分数组（O(n)）

**关键观察（视角转换）**：暴力是"站在 k 的角度，逐个问每个元素得不得分"。但反过来，**站在元素的角度看**，每个元素 `nums[i]` 的得分条件是 `k` 落在一个连续区间上。于是问题从"对每个 k 数数"变成"统计哪个 k 被最多区间覆盖"。

**两段区间的推导**：

新下标 `(i-k) mod n`，得分条件 `nums[i] <= (i-k) mod n`，分两种情况：

- **`k <= i`**：`i-k ≥ 0`，未绕环，新下标 = `i-k`。
  得分条件 `nums[i] <= i-k` ⟺ `k <= i-nums[i]`。
  区间：**`[0, i-nums[i]]`**（仅当 `i-nums[i] ≥ 0` 即 `nums[i] ≤ i` 时存在）。

- **`k > i`**：`i-k < 0`，绕环，新下标 = `i-k+n`。
  得分条件 `nums[i] <= i-k+n` ⟺ `k <= i-nums[i]+n`。
  区间：**`[i+1, i-nums[i]+n]`**（下界 `i+1` 需 `< n` 才非空；上界与 `[0, n-1]` 取交集）。

**两段区间不重叠**：第一段上界 ≤ `i`，第二段下界 = `i+1`，最多相邻。当 `nums[i]=0` 时第一段 `[0,i]` 与第二段 `[i+1,...]` 恰好拼满（元素值 0 恒 ≤ 任何下标，所有 k 都得分，合理）；当 `nums[i]>0` 时两段之间隔着 `[i-nums[i]+1, i]` 这段不得分的空隙（长度恰好 `nums[i]`，因为元素总的得分 k 数量应为 `n-nums[i]`）。

**为什么不能逐点标记**：每个元素区间平均长度 O(n)，逐点 +1 又回到 O(n²)。改用**差分数组**：只记录区间端点的变化量（起点 `+1`、终点后一位 `-1`），一次前缀和把所有区间的贡献摊到每个 k 上，总复杂度 O(n)。

### 复杂度对比

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|:----------:|:----------:|------|
| 暴力枚举 | O(n²) | O(1) | 简单直观，作为验证基准 |
| 差分数组 | O(n) | O(n) | 区间批量标记 + 前缀和还原 |

## 2. 代码实现

代码位置：`Algorithm-Cote/src/leetCode/difficult/BestRotation.java`

### 暴力解法（验证基准）

```java
/**
 * 暴力：枚举所有 k，逐个元素判断是否得分。O(n²)，数据大时超时。
 */
public int bestRotation(int[] nums) {
    int n = nums.length;
    int maxScore = Integer.MIN_VALUE;
    int maxIndex = 0;
    for (int k = 0; k < n; k++) {
        int curScore = 0;
        for (int i = 0; i < n; i++) {
            // 轮调 k 后，原下标 i 的元素新下标为 (i-k) mod n
            if (i < k && nums[i] <= n - k + i) {  // i-k<0，绕环后新下标 = i-k+n
                curScore++;
            }
            if (i >= k && nums[i] <= i - k) {     // i-k>=0，未绕环，新下标 = i-k
                curScore++;
            }
        }
        if (curScore > maxScore) {
            maxScore = curScore;
            maxIndex = k;   // k 从小到大，严格大于才更新，保证取最小 k
        }
    }
    return maxIndex;
}
```

### 差分解法（最优）

```java
/**
 * 差分：每个元素把"得分 k 的区间"映射到差分数组上，前缀和还原每个 k 的得分。
 * 区间起点 +1，终点后一位 -1，一趟扫描累加即可得到每个 k 的得分。
 */
public int bestRotation2(int[] nums) {
    int n = nums.length;
    int[] diff = new int[n + 1];   // 多开一位，供区间结束标记 r+1 == n 使用
    for (int i = 0; i < nums.length; i++) {
        int value = nums[i];

        // 第一段区间 [0, i-value]：对应 k <= i 且 nums[i] <= i-k
        if (i - value >= 0) {            // 仅当 i-value >= 0 时区间存在
            diff[0]++;                    // 区间起点 +1
            diff[i - value + 1]--;        // 区间终点后一位 -1
        }

        // 第二段区间 [i+1, min(i-value+n, n-1)]：对应 k > i 且 nums[i] <= i-k+n
        if (i + n - value > i && i + 1 < n) {   // value < n 恒成立；i+1 < n 才非空
            diff[i + 1]++;                        // 区间起点 i+1 处 +1
            int end = Math.min(i + n - value, n - 1);  // 上界截断到 n-1
            diff[end + 1]--;                      // 终点后一位 -1，end+1 <= n 不越界
        }
    }
    int maxIndex = 0;
    int maxScore = Integer.MIN_VALUE;
    int curScore = 0;
    for (int i = 0; i < diff.length; i++) {
        curScore += diff[i];          // 前缀和还原：i 处就是轮调 i 的得分
        if (curScore > maxScore) {
            maxScore = curScore;
            maxIndex = i;
        }
    }
    return maxIndex;
}
```

**关键细节**：
- `diff` 长度 `n+1`：区间结束标记放在 `end+1`，`end` 最大 `n-1`，所以 `end+1` 最大 `n`，不会越界
- 第一段判断 `i-value >= 0`：区间起点固定是 0
- 第二段判断 `i+1 < n`：下界超过 `n-1` 则整段为空；`i+n-value > i` 恒成立（因 `value ≤ n-1`），可省略
- 最后扫描 `diff` 全长度：`diff[n]` 处是纯负数（区间收尾），`curScore` 只会下降，不会把 `maxIndex` 错置为 `n`

## 3. 踩坑记录

1. **负数取模：数学 mod vs Java `%`**
   - 数学取模结果在 `[0, n-1]`，如 `(-2) mod 5 = 3`
   - Java `-2 % 5 = -2`（符号跟随被除数），若要数学结果需写 `((x % n) + n) % n`
   - 推导区间时用的都是数学 mod，千万别把 Java 的 `%` 行为代入

2. **暴力版 `i < k` 分支漏了 `i`**（第一版实现）
   - `i < k` 时新下标 = `i-k+n`，得分条件应为 `nums[i] <= i-k+n`，即 `nums[i] + k - i <= n`
   - 最初误写成 `nums[i] <= n-k`（少了 `+ i`）
   - 这个 bug 用 `{2,3,1,4,0}` 测不出来，因为该用例 `i<k` 分支只有 `i=0` 参与，此时 `i-k+n` 恰好等于 `n-k`；改用 `{2,3,4,4,0}`（正确 k=3）才能暴露

3. **第二段区间下界写错**
   - 第二段是 `(i, i+n-value]`，起点是 **`i+1`**，不是 `i`（`k > i` 时才能绕环到 `i-k+n`）
   - 误写 `diff[i]++` 会让 k=i 也被错误计分

4. **区间结束标记的位置与符号**
   - 区间 `[L, R]` 的结束标记在 **`R+1`** 处 `-1`，不是 `R` 处
   - 结束标记是 `-1`（`--`），不是 `+1`
   - 上界要**截断到 `n-1`**（k 的范围是 `[0, n-1]`），不能只截到 `n`

5. **`diff[i+1]++` 写了两次**（多行重复）
   - 会导致第二段区间重复计分，分数全部虚高，但某些用例下答案可能碰巧正确，极难用单个用例发现——**必须用随机对拍验证**

6. **对拍验证**：单用例无法覆盖所有边界，写一个随机生成数组、暴力 vs 差分结果对比的测试，跑几千组，是验证算法正确性最可靠的手段

## 4. 技巧总结

| 技巧 | 说明 | 相关笔记 |
|------|------|----------|
| **差分数组** | 多次区间加 + 最终结果查询，端点 O(1) 标记 + 前缀和还原 | [经典解法/差分.md](../经典解法/差分.md) |
| **负数取模** | 数学 mod 结果在 `[0,n-1]`，环形下标问题用 `(i-k) mod n` 表达 | 见踩坑记录 |
| **对拍验证** | 暴力作为基准，随机数据对比两种解法输出 | 见踩坑记录 |

**思维要点**：
- **视角转换**：从"站在 k 逐个问元素"翻转到"站在元素划出得分区间"，把"判断问题"变成"覆盖计数问题"，是差分能用的前提
- **批量代替逐点**：区间整体 +1 用端点标记 + 前缀和摊还，避免 O(区间长度) 的逐点操作
- **覆盖计数**：差分就是"快速统计哪个点被最多区间覆盖"的经典工具（同 732.日程安排表 III）

## 5. 思考过程

这道题是从"暴力先跑通"到"差分优化"的完整链路，记录的思考脉络如下：

1. **最初想法**：先写暴力验证正确性。推导中自己发现轮调 k 后元素的新下标是 `(i-k) mod n`，按 `k<=i` 和 `k>i` 分两支判断。但第一版 `i<k` 分支漏了 `+i`，用原题示例测不出来，后来构造 `{2,3,4,4,0}` 才暴露。

2. **讨论负数取模**：推导时对 `(i-k) mod n` 的负数情况不熟，澄清了数学取模（结果 `[0,n-1]`）与 Java `%`（符号跟随被除数）的区别，理解了"轮调就是下标减 1、越界环形绕回"。

3. **发现规律**：把每个元素的得分条件改写成 `k <= i-nums[i]` 和 `k <= i-nums[i]+n`，意识到每个元素得分的 `k` 不是散点而是**连续区间**（两段，有上界，环绕）。

4. **关键思维转折**：最初以为区间是"某个值到 +∞"，讨论后发现因为有上界、又是循环，线性展开是两段。随后意识到问题等价于"哪个 k 被最多区间覆盖"——这一步把"逐个元素判断"转换成了"区间覆盖计数"。

5. **引入差分**：明白"逐点填充"仍会退化 O(n²)，必须"只在端点挂 ±1 牌子，管理员走一遍累加"，即差分数组。自己动手实现时犯了几个边界错误：第二段下界应为 `i+1`、结束标记应在 `R+1` 处 `-1`、上界截断到 `n-1`。

6. **最终验证**：单用例不够，编写随机对拍（暴力 vs 差分跑几千组）才放心。最终 O(n) 解出答案，也彻底理解了"站在元素视角划区间 + 差分统计覆盖"这一整套思维范式。
