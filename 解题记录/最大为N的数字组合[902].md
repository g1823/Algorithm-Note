# 最大为 N 的数字组合 [902]

## 1. 解题思路

### 问题描述

给定一个有序字符串数组 `digits`（是 `'1'-'9'` 的子集，不含 `0`，已排序）和一个整数 `N`，可以用 digits 中的数字**无限次**组成数字，求能组成的小于等于 `N` 的正整数个数。

**示例**：`digits = ["1","3","5","7"], N = 100` → 输出 20

### 核心难点

这是一道"不标准"的数位DP题。与经典数位DP的区别在于：

| | 经典数位DP | 本题 |
|--|-----------|------|
| 可选数字 | 0~9 连续 | digits 子集（不含0） |
| 前导零 | 必须用 leadZero 标记，否则 `01` 和 `1` 重复计数 | **不需要 leadZero**（因不含 0） |
| 短位数数字 | 通过 skip 分支（前导零跳过）自然枚举 | 单独用公式计算 |

核心洞察：**digits 不含 0**，所以不能用前导零的 skip 机制来枚举短位数数字。但换个角度看——既然不含 0，也就不用担心 `01` 和 `1` 的重复计数问题，短位数的情况可以直接用排列组合公式算。

### 算法设计

**两步走策略**：

1. **短位数（位数 < len(N)）**：每一位都可以从 digits 中任选，总数 = `m^1 + m^2 + ... + m^{len-1}`
2. **同位数（位数 = len(N)）**：用数位DP逐位枚举，`isLimit` 控制不超过 N

**DFS 参数**：
- `cur`：当前处理的下标
- `isLimit`：之前各位是否都与 N 的前缀一致

**终止条件**：`cur == len(N)` → 返回 1（构造出一个合法数字）

**状态转移**：对每个 `digitNum ∈ digits`，若 `digitNum ≤ up`，递归下一层

**缓存**：`!isLimit` 时，后续结果只与剩余长度有关，用 `memo[cur]` 缓存

### 与标准数位DP模板的对比

```
标准模板: dfs(cur, isLimit, leadZero)    →  需要 skip 分支
本题:     dfs(cur, isLimit)             →  短位数用公式，DFS 只跑同位数
```

### 代码流程

```
atMostNGivenDigitSet(digits, N)
  ├── 解析 digits 为 int 数组 digitNums
  ├── 提取 N 的十进制各位到 nums（高位在前）
  ├── 公式计算少位数总和: sum += m^i (i=1..len-1)
  ├── 初始化 memo[len] = -1
  └── 返回 sum + dfs(0, true)

dfs(cur, isLimit)
  ├── cur == len → return 1
  ├── !isLimit && memo[cur] ≠ -1 → return memo[cur]
  ├── up = isLimit ? nums[cur] : 9
  ├── 遍历 digitNums:
  │   └── digit ≤ up → dfs(cur+1, isLimit && digit == up)
  ├── !isLimit → memo[cur] = res
  └── return res
```

## 2. 代码实现

```java
public class AtMostNGivenDigitSet {
    int[] memo;
    int[] nums;
    int[] digitNums;

    public int atMostNGivenDigitSet(String[] digits, int n) {
        digitNums = new int[digits.length];
        for (int i = 0; i < digits.length; i++) {
            digitNums[i] = digits[i].charAt(0) - '0';
        }
        // 提取n的十进制各位数字（高位在前）
        int[] temp = new int[32];
        int length = 0, t = n;
        while (t > 0) {
            temp[length++] = t % 10;
            t /= 10;
        }
        nums = new int[length];
        for (int i = length - 1; i >= 0; i--) {
            nums[i] = temp[length - 1 - i];
        }
        // 位数少于len(N)的数字，每一位可以任意选
        int m = digitNums.length;
        int res = 0;
        int pow = 1;
        for (int i = 1; i < length; i++) {
            pow *= m;
            res += pow;
        }
        memo = new int[length];
        Arrays.fill(memo, -1);
        return res + dfs(0, true);
    }

    public int dfs(int cur, boolean isLimit) {
        if (cur == nums.length) {
            return 1;
        }
        if (!isLimit && memo[cur] != -1) {
            return memo[cur];
        }
        int up = isLimit ? nums[cur] : 9;
        int res = 0;
        for (int digitNum : digitNums) {
            if (digitNum > up) {
                break;
            }
            res += dfs(cur + 1, isLimit && digitNum == up);
        }
        if (!isLimit) {
            memo[cur] = res;
        }
        return res;
    }
}
```

## 3. 踩坑记录

### 1) 误用二进制提取

**错误写法**：
```java
temp[length++] = t & 1;
t >>= 1;
```

提取的是 N 的二进制位（如 N=100 变成 1100100），但 digits 是十进制数字，后续比较完全错位。

**修正**：用 `t % 10` / `t /= 10` 提取十进制位。

### 2) `isLimit` 传递时比较的是值，不是索引

**错误写法**：
```java
res += dfs(cur + 1, isLimit && i == up, ...);
```

`i` 是循环索引，不是 digitNums[i] 的值。当索引恰好等于 up 时也会错误地限制后续。

**修正**：
```java
res += dfs(cur + 1, isLimit && digitNum == up);
```

### 3) 缺少短位数处理

最初的实现想用一个统一的 DFS 带 leadZero 来处理所有情况，但 digits 不含 0，导致永远无法通过前导零跳过当前位（因为可选数字中没有 0），短位数数字全部漏掉。

**修正**：拆开处理——短位数用公式，DFS 只跑同位数。

## 4. 技巧总结

- **数位DP的参数量不是固定的**：当 digits 不含 0 且 DFS 只处理同位数时，可以省略 `leadZero` 参数，大幅简化代码
- **分治思维**：短位数（必然小于 N）和同位数（需要精确比较）分开处理，各取所需
- **公式与 DFS 结合**：少位数用排列组合公式 `m^i` 直接计算，避免递归开销
- **非连续数字集合的数位DP**：枚举时从 digits 遍历而非 0~9 遍历，`up` 仍用于剪枝
- **简化缓存**：当只有 `isLimit` 一个布尔参数时，缓存的 key 只需 `cur` 即可

## 5. 思考过程

### 第一次尝试：套用标准数位DP模板

最初以为这就是标准数位DP，只是枚举范围从 `0~up` 改成 `digits` 集合。写成带 `(cur, isLimit, leadZero)` 的三参数 DFS。

### 发现问题

测试 D=[1,3,5,7], N=100 时返回 0，预期 20。

分析发现：
- digits 不含 0，所以前导零状态下无法通过选 0 跳过当前位
- 没有 skip 分支，短位数数字全部被漏掉了

### 讨论后修正

意识到这道题的特殊性在于"数字集合不含 0"，导致：
- 传统靠前导零 + 选 0 跳过位的策略失效
- 但同时也带来了好处：不需要担心 `01` 和 `1` 的重复计数

于是采用"拆开算"策略：
- 短位数：直接公式计算
- 同位数：简化为 `(cur, isLimit)` 的 DFS

### 最终理解

这道题看似是标准数位DP，但因为 digits 不含 0 这个特性，反而可以用更简洁的方式求解。同时也加深了对数位DP中前导零作用的理解——前导零的核心作用是"允许跳过当前位，从而构造出更短的数字"。
