# 474. 一和零

## 1. 解题思路

**题目**：给你一个二进制字符串数组 `strs` 和两个整数 `m` 和 `n`。请你找出并返回 `strs` 的最大子集大小，该子集中**最多**有 `m` 个 `0` 和 `n` 个 `1`。每个字符串只能使用一次。

**示例**：`strs = ["10","0001","111001","1","0"], m = 5, n = 3`，最大子集是 `{"10","0001","1","0"}`，共 4 个。

**核心难点**：识别这是一个**多维费用的 0/1 背包问题**，并正确执行 0/1 背包的两条铁律——外层遍历物品、内层容量**逆序**。

**问题定性（多维 0/1 背包）**

每个字符串就是一个**物品**，重量拆成两维（`zeros` 个 0、`ones` 个 1），有两个容量限制（0 的个数上限 m、1 的个数上限 n）。每件物品**只能选一次**，目标是最大化装入的物品数量。这比普通 0-1 背包多了一个容量维度，即"二维费用背包"。

**与 [518. 零钱兑换 II](零钱兑换II[518].md) 的本质区别（务必分清）**

| 维度 | 零钱兑换 II (518) | 一和零 (474) |
|------|-------------------|--------------|
| 背包类型 | **完全背包**（硬币无限量） | **0/1 背包**（字符串只有一份） |
| 内层容量遍历 | **正序**（允许重复拿） | **逆序**（防止重复拿） |
| dp 含义 | 凑出金额 i 的**方案数** | 用 i 个 0、j 个 1 能装的**最大物品数** |

两者的遍历顺序完全相反——这是最容易踩的大坑。

**状态定义**

`dp[i][j] = k`：在"当前已遍历过的前若干个字符串"中，**恰好**使用 `i` 个 `0` 和 `j` 个 `1` 时，能组成的**最大字符串个数** `k`。

- "前若干个"这一阶段由**外层循环**隐式提供，每一轮代表一个新的决策阶段（考虑一个新字符串）。
- "恰好使用 i 个 0、j 个 1"：由于目标是"最多 m 个 0、n 个 1"，最终答案是 `dp[m][n]`——dp 数组天然容忍"用不满"，因为容量更大的格子存的是最优值。

**状态转移方程**

对当前字符串 s（含 zeros 个 0、ones 个 1）：

```
dp[i][j] = max(dp[i][j], dp[i - zeros][j - ones] + 1)
```

即：**不选** s（保持原状） vs **选** s（腾出 zeros/ones 容量，个数 +1）。

**复杂度**：时间 O(strs.length × m × n)，空间 O(m × n)。

### 为什么外层必须遍历物品（字符串）？

外层循环代表"决策的时间轴"。只有把物品放在外层，程序才知道"截止目前，我已经考虑完了前 k 个物品"。

若**外层遍历容量、内层遍历物品**，程序会失去"已处理物品"的边界感：在计算不同容量格子时，会反复把同一个字符串拿来使用，完全乱套。

### 为什么内层容量必须逆序（从大到小）遍历？

这是 **0/1 背包的铁律**。逆序保证了计算 `dp[i][j]` 时，它所依赖的 `dp[i - zeros][j - ones]` 依然停留在"上一个字符串（前 k-1 个）"的**旧状态**，尚未被本轮（第 k 个字符串）更新。

**深度答疑：逆序时"后面的数据依赖前面"，但前面本轮没填，不会出问题吗？**

完全不会。这里依赖的是**上一轮（旧）的前面**，而不是本轮（新）的前面：

- **正序**会先更新小容量，导致大容量计算时误用"本轮新数据"，相当于把同一个字符串用了多次（退化为完全背包）。
- **逆序**会先更新大容量，此时小容量还是旧的，完美避免重复使用——这就是精妙之处。

## 2. 代码实现

```java
public class FindMaxForm {

    /**
     * 一和零 —— 多维费用 0/1 背包
     * dp[i][j] = k：当前物品（前 n 个字符串）下，用 i 个 0 和 j 个 1，最多能选出的字符串个数。
     * 外层遍历每个字符串（决策阶段），统计 zeros/ones；
     * 内层二维容量必须严格逆序，避免同一字符串被重复选择。
     */
    public int findMaxForm(String[] strs, int m, int n) {
        int[][] dp = new int[m + 1][n + 1];

        // 外层循环：遍历每一个字符串（决策阶段）
        for (String s : strs) {
            int zeros = 0, ones = 0;
            // 统计当前字符串的 0 和 1 的数量
            for (char c : s.toCharArray()) {
                if (c == '0') zeros++;
                else ones++;
            }

            // 内层循环：二维容量必须严格逆序（从大到小），保证每个字符串只能被选一次
            for (int i = m; i >= zeros; i--) {
                for (int j = n; j >= ones; j--) {
                    // 状态转移：不选 vs 选
                    dp[i][j] = Math.max(dp[i][j], dp[i - zeros][j - ones] + 1);
                }
            }
        }
        return dp[m][n];
    }
}
```

## 3. 踩坑记录

- **误当成完全背包写成内层正序**：若内层容量正序遍历，同一个字符串会被重复选取（每个字符串当成无限量），结果偏大。本题字符串只有一个，**必须内层逆序**（0/1 背包铁律）。
- **外层遍历容量、内层遍历物品**：程序失去"已处理物品"的阶段边界感，会把同一物品反复用于不同容量格子，结果错误。**物品必须在外层**。
- **统计 zeros/ones 放在外层循环内每次重算**：注意每个字符串的 zeros/ones 需在进入内层前现算，不能提前混用。
- **容量越界**：二维内层循环下界取 `i >= zeros`、`j >= ones`，否则 `dp[i-zeros][j-ones]` 下标为负。
- **与 518 混淆**：518 完全背包内层正序求组合方案数，474 0/1 背包内层逆序求最大个数——两道题必须对照着记，单看一道极易写反（详见 [518 笔记](零钱兑换II[518].md)）。

## 4. 技巧总结

- **识别多维背包**：物品消耗的"资源"超过一种（这里 0 和 1 各占一维容量），就把 dp 维度扩到与资源种类一致 → 二维费用背包。
- **0/1 vs 完全，只看一件事**：物品能不能重复选。能重复 → 内层正序；不能重复 → 内层逆序。与"求最值还是方案数"无关。
- **压缩一维时的方向**：dp 从二维 `dp[k][i][j]` 压缩为 `dp[i][j]` 时，内层两维都要逆序，原因与一维 0/1 背包完全相同——依赖旧状态。
- **通用判定口诀**：
  - 外层物品 + 内层**正序** = 完全背包；
  - 外层物品 + 内层**逆序** = 0/1 背包；
  - 外层容量 + 内层物品 = 求**排列数**（见 518 笔记）。
- 同类二维背包/多重资源题可归入 [背包应用](../经典解法/03-动态规划/背包应用.md) 专题体系。
