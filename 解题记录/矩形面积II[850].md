# 850. 矩形面积 II

## 1. 解题思路

### 问题本质

给定 N 个轴对齐矩形 `[x1, y1, x2, y2]`，求它们在平面上的**并集面积**（重叠部分只算一次），结果模 1e9+7。

核心难点：矩形数量 ≤ 200，坐标 ≤ 1e9，无法逐个像素遍历，必须用离散化 + 区间合并。

### 思路演变过程

**阶段一：线段树 × 线段树（被排除）**

最初认为需要在 x 轴和 y 轴同时构造线段树，即二维线段树。每个离散化的 x 区间对应一个完整的 y 区间，似乎需要"线段树 × 线段树"来维护二维覆盖信息。这种做法的代码复杂度高、常数大，且本题不需要二维查询（只需整个平面的面积），属于过度设计。

**阶段二：扫描线 + 优先队列（被排除）**

参考「218. 天际线问题」的思路：沿 x 轴扫描，用优先队列维护当前活跃的 y 区间。但**优先队列无法处理重叠区间的合并**——优先队列只能给出堆顶元素，而多个矩形在 y 轴上可能部分重叠，合并后的实际覆盖长度需要全局计算。这是本质区别：天际线只需要 max height，而矩形面积需要**并集长度**。

**阶段三：扫描线 + 线段树（最终方案）**

正确方案：**降维**，将二维问题拆成两个一维问题：

1. 沿 x 轴的**扫描线**，将每个矩形拆成"入边"和"出边"两个事件
2. 在 y 轴上维护一个**线段树**，支持区间添加/删除覆盖次数，并查询当前被覆盖的总长度

面积计算公式：
```
area += (next_x - current_x) × tree.getTotalCoveredYLength()
```

每次处理完某个 x 坐标上的所有事件后，线段树就反映了当前该 x 位置上的 y 区间覆盖状态。这个状态持续到下一个 x 事件出现为止。

### 为什么不需要 lazy 下推

本题线段树的特殊性：每个节点维护自己的 `cnt`（该区间被完整覆盖的次数），且加和减是成对出现的（一个矩形入边 +1，出边 -1）。当 `cnt > 0` 时，该区间被完全覆盖，长度直接取 `ys[r+1] - ys[l]`；当 `cnt == 0` 时，长度从子节点聚合而来。

**不需要下推的原因**：`cnt` 是"独占"的——父节点 `cnt > 0` 时直接用全长，根本不看子节点；父节点 `cnt == 0` 时才需要聚合子节点。子节点的 `cnt` 始终独立更新，不受父节点影响。

### 与标准离散线段树的区别

| 特性 | 标准离散线段树（区间赋值/求和） | 本题的线段树 |
|------|-------------------------------|-------------|
| 更新语义 | SET 或 ADD，需要 lazy 下推 | 区间覆盖次数加减（`cnt += ±1`） |
| 查询目标 | 区间最值或区间和 | 根节点的总覆盖长度 |
| lazy 下推 | 必须 | 不需要（cnt 独立） |
| 子节点值 | 依赖父节点下推 | 独立更新 |

## 2. 代码实现

### solution2（标准写法，推荐）

```java
class SegTree {
    int[] cover;  // 节点被完整覆盖的次数
    int[] len;    // 节点覆盖的有效 y 轴长度
    int[] ys;     // 离散化后的 y 坐标
    int n;        // 区间个数 = ys.length - 1

    SegTree(int[] ys) {
        this.ys = ys;
        this.n = ys.length - 1;
        cover = new int[n * 4];
        len = new int[n * 4];
    }

    void update(int y1, int y2, int val) {
        int l = Arrays.binarySearch(ys, y1);
        int r = Arrays.binarySearch(ys, y2);
        if (l < 0 || r < 0 || l >= r) return;
        update(1, 0, n - 1, l, r - 1, val);
    }

    private void update(int node, int l, int r, int ql, int qr, int val) {
        if (ql > r || qr < l) return;
        if (ql <= l && r <= qr) {
            cover[node] += val;  // 增删统一为 ±1
        } else {
            int mid = (l + r) / 2;
            update(node * 2, l, mid, ql, qr, val);
            update(node * 2 + 1, mid + 1, r, ql, qr, val);
        }
        // 尾部统一重新计算长度
        if (cover[node] > 0) {
            len[node] = ys[r + 1] - ys[l];
        } else if (l == r) {
            len[node] = 0;
        } else {
            len[node] = len[node * 2] + len[node * 2 + 1];
        }
    }
}
```

扫描线主流程：

```java
public int rectangleArea(int[][] rectangles) {
    Set<Integer> ySet = new HashSet<>();
    List<int[]> events = new ArrayList<>();
    for (int[] r : rectangles) {
        ySet.add(r[1]); ySet.add(r[3]);
        events.add(new int[]{r[0], r[1], r[3], 1});   // 入边
        events.add(new int[]{r[2], r[1], r[3], -1});  // 出边
    }
    events.sort(Comparator.comparingInt(a -> a[0]));

    int[] ys = ySet.stream().sorted().mapToInt(Integer::intValue).toArray();
    SegTree seg = new SegTree(ys);

    long ans = 0;
    int prevX = events.get(0)[0];
    int MOD = 1_000_000_007;

    for (int[] e : events) {
        int x = e[0], y1 = e[1], y2 = e[2], type = e[3];
        ans = (ans + (long)(x - prevX) * seg.len[1]) % MOD;
        seg.update(y1, y2, type);
        prevX = x;
    }
    return (int) ans;
}
```

## 3. 踩坑记录

### 坑 1：线段树建在坐标点上而非区间上

**错误写法**：`n = ys.length`，树节点覆盖 `[ys[left], ys[right]]`（闭区间）。

**问题**：
- 叶子节点（`left == right`）长度为 0，因为 `ys[right] - ys[left] = 0`
- 分区 `mid = (l+r)/2` 后，左右孩子为 `[l, mid]` 和 `[mid+1, r]`，区间 `[ys[mid], ys[mid+1]]` 被遗漏

**举例**：`ys = [0, 2, 5, 10]`，矩形覆盖 `[y=2, y=10)` 对应索引范围 `[1, 3)`。

- 根 `[0, 3]`，mid=1
- 左孩子 `[0,1]` 覆盖 `[ys[0], ys[1]] = [0, 2]`
- 右孩子 `[2,3]` 覆盖 `[ys[2], ys[3]] = [5, 10]`
- 区间 `[ys[1], ys[2]] = [2, 5]` 凭空消失了！

**修复**：`n = ys.length - 1`，树建在**区间**上（每个区间 `[ys[i], ys[i+1])`），节点 `[l, r]` 对应 y 范围 `[ys[l], ys[r+1])`，长度 = `ys[r+1] - ys[l]`。

### 坑 2：叶子节点无子节点，聚合时数组越界

`count == 1` 分支和 `count == 0` 分支在叶子节点上都会尝试访问 `nodes[node*2]` 和 `nodes[node*2+1]`，但叶子节点作为树的最后一层，其子节点索引超出了数组大小，导致 `ArrayIndexOutOfBoundsException`。

**修复**：在聚合前判断 `left == right`，叶子节点直接置长度 0。

### 坑 3：事件同 x 的处理

最初的事件处理逻辑是"逐个处理"，遇到同 x 的入边和出边时，二者处理顺序会影响中间状态的正确性。例如出边先于入边时，矩形重叠区域在中间时刻被错误清零。

**修复方法一（batching）**：按 x 坐标分组，先计算面积，再将同 x 的事件一次性处理完。

**修复方法二（逐个处理 + 零宽度自动跳过）**：逐个处理事件，由于同 x 事件的 `x - prevX = 0`，面积贡献为 0，中间状态的错误不会影响最终结果。推荐此方法，代码更简洁。

## 4. 技巧总结

### 扫描线（Sweep Line）

将二维问题降为一维的关键技巧。

要点：
- 每个矩形拆成"入边"和"出边"两个事件
- 所有事件按 x 排序
- 扫描过程中维护当前 y 轴上的活跃区间

### 线段树维护区间并长度

一种特殊的线段树用法，不需要 lazy 下推：
- `cnt` 表示该区间被完整覆盖的次数
- `cnt > 0`：长度为 `ys[r+1] - ys[l]`
- `cnt == 0` && `l == r`：长度为 0
- `cnt == 0` && `l != r`：长度为左右子节点长度之和

### 离散化

由于坐标范围 1e9，必须将 y 坐标排序去重，建立从原始值到区间索引的映射。每个区间 `[i, i+1)` 对应 y 坐标范围 `[ys[i], ys[i+1])`。

## 5. 思考过程

### 第一次接触：从二维线段树到降维

最初看到"矩形面积"和"重叠"两个关键词，第一反应是二维线段树。但随后意识到题目只要求总面积，不需要查询某个具体点的覆盖情况，二维线段树过重。

想起了「218. 天际线问题」的扫描线思路——那题用扫描线 + 优先队列处理建筑轮廓，但优先队列无法处理"多个矩形在 y 轴上部分重叠"这种复杂情况。才意识到需要线段树来维护 y 区间的并集长度。

### 理解线段树的特殊性

讨论的焦点集中在"为什么不需要 lazy 下推"——这是本题线段树和其他线段树最不一样的地方。核心在于 `cnt` 的语义：它表示"有多少个矩形完整覆盖了这个区间"，而"完整覆盖"意味着这个区间不需要看子节点了。只有当 `cnt == 0` 时，才需要从子节点聚合。加和减是成对出现的，所以永远不需要把父节点的 `cnt` 往下推。

### 第一次编码的失误

编写第一版代码时，直接把 `n = ys.length`，建了一个基于坐标点的线段树。测试时才意识到离散化后的线段树应该基于区间（y_i 到 y_{i+1} 之间的间隔），而不是基于坐标点本身。这个错误花了不少时间定位，因为它在某些输入下能跑出正确结果（当矩形的 y 范围刚好覆盖离散化点的区间边界时），但在更一般的情况下会遗漏部分区间。

### 叶子节点越界

fix 完区间问题后，大量输入依然报 `ArrayIndexOutOfBoundsException`。排查发现是删除分支中，当 `count[node] == 1`（矩形离开，覆盖次数归零）时，代码尝试从子节点聚合长度，但叶子节点根本没有子节点，`node*2` 索引超过了数组大小。

### 标准写法重构

在解决所有 bug 之后，将代码重构为标准写法：
- 用 `Arrays.binarySearch` 替代 `HashMap` 做 y 坐标映射
- 用 `int val = ±1` 替代 `boolean isAdd` 做增删标识
- 长度计算统一放在方法尾部，只有三路判断
- 主循环不需要按 x 分批，同 x 事件本身宽度为 0 自动跳过

重构后的代码代码量减少约 40%，逻辑更清晰，且更接近"区间覆盖长度线段树"的模板写法。
