# 218. 天际线问题

## 1. 解题思路

**核心难点**：如何快速获取当前所有活跃建筑的最高高度，并在高度变化时记录关键点。

一个建筑 `[L, R, H)` 表示在 x ∈ [L, R) 区间内高度为 H。最终输出的天际线是所有活跃建筑**取 max** 后的轮廓线——相邻 x 之间高度不变，只有在建筑开始或结束时高度才可能变化。

---

### 解法一：线段树（区间覆盖取 max + DFS 收集）

**思路**：将问题转化为"多次区间取 max 覆盖，最后输出每个区间的结果"。

- 离散化所有 L、R 坐标，相邻坐标之间形成一个**段**
- 建筑 `[L, R, H)` 覆盖连续的一段段索引范围
- 线段树每个节点维护"该区间统一高度"，取值规则：
  - `非 -1`：表示该区间被统一覆盖为某个高度
  - `-1`：表示子区间高度不一致，需往下查
- 更新时取 max 覆盖（不是累加）
- 全部更新完后，DFS遍历线段树，收集每个段的高度
- 遍历时通过 `value[node] != -1` 快速跳过统一区间
- 最后合并相邻等高的关键点

**复杂度**：O((N+M) log M)，M为离散化后坐标数量

---

### 解法二：扫描线 + 优先队列（延迟删除）

**思路**：天际线变化只发生在建筑的左右边界处，因此可以"扫描"这些事件点，实时维护当前最高高度。

- 为每个建筑生成两个事件：
  - 进入 (L, H)：加入优先队列
  - 离开 (R, H)：标记为待删除
- 按 x 排序事件，同一 x 的事件必须全部处理完再检查高度
- 检查高度前，将堆顶已被标记的删除项弹出（prune）
- 当前最高高度与上一高度不同时，记录关键点 `[x, height]`

**核心数据结构**：最大堆（取最高） + HashMap（延迟删除，避免堆不支持 O(log n) 随机删除）

**复杂度**：O(N log N)

---

## 2. 代码实现

完整代码详见 `Algorithm-Cote/src/leetCode/difficult/GetSkyline.java`，包含两个独立解法：

### 解法一核心框架

```java
// 离散化
Set<Integer> set = new HashSet<>();
for (int[] b : buildings) { set.add(b[0]); set.add(b[1]); }
int[] points = set.stream().sorted().mapToInt(Integer::intValue).toArray();
Map<Integer, Integer> idx = new HashMap<>();
for (int i = 0; i < points.length; i++) idx.put(points[i], i);

// 线段树更新（取 max 覆盖）
SegmentTree seg = new SegmentTree(points.length);
for (int[] b : buildings) {
    seg.update(idx.get(b[0]), idx.get(b[1]) - 1, b[2]);
}

// DFS 遍历收集
List<int[]> raw = new ArrayList<>();
seg.dfs(1, 0, points.length - 1, points, raw);

// 合并相邻等高
List<List<Integer>> res = new ArrayList<>();
for (int[] p : raw) {
    if (res.isEmpty() || !res.get(res.size()-1).get(1).equals(p[1]))
        res.add(Arrays.asList(p[0], p[1]));
}
```

线段树的关键在于 update 时的 max 覆盖逻辑和 `value[node] == -1` 的合并标记：

```java
// 全包含 + 节点为统一值 → 直接覆盖
if (left >= updateLeft && right <= updateRight && value[node] != -1) {
    value[node] = val;
    lazy[node] = val;
    return;
}
// 否则 pushDown 递归
pushDown(node);
update(leftChild, ...);
update(rightChild, ...);
// 合并子节点
value[node] = (value[left] == value[right]) ? value[left] : -1;
```

DFS 遍历时根据 `value[node]` 是否等于 -1 决定是否继续向下：

```java
if (value[node] != -1) {           // 区间统一高，直接收集
    out.add(new int[]{points[left], value[node]});
    return;
}
// 否则 pushDown 后递归
pushDown(node);
dfs(leftChild, ...);
dfs(rightChild, ...);
```

### 解法二核心框架

```java
// 生成事件
List<Event> events = new ArrayList<>();
for (int[] b : buildings) {
    events.add(new Event(b[0], b[2], true));   // 进入
    events.add(new Event(b[1], b[2], false));  // 离开
}
events.sort(Comparator.comparingInt(a -> a.x));

Map<Integer, Integer> pending = new HashMap<>();  // 待删除标记
PriorityQueue<Integer> pq = new PriorityQueue<>((a,b)->Integer.compare(b,a));
List<List<Integer>> res = new ArrayList<>();
int preMax = 0, i = 0;

while (i < events.size()) {
    int x = events.get(i).x;
    // 处理完同一 x 的所有事件
    while (i < events.size() && events.get(i).x == x) {
        Event e = events.get(i++);
        if (e.isLeft) {
            pq.add(e.height);
        } else {
            pending.put(e.height, pending.getOrDefault(e.height, 0) + 1);
        }
    }
    // 延迟删除：弹出被标记的堆顶
    while (!pq.isEmpty() && pending.getOrDefault(pq.peek(), 0) > 0) {
        int h = pq.poll();
        pending.put(h, pending.get(h) - 1);
        if (pending.get(h) == 0) pending.remove(h);
    }

    int curMax = pq.isEmpty() ? 0 : pq.peek();
    if (curMax != preMax) {
        res.add(Arrays.asList(x, curMax));
        preMax = curMax;
    }
}
```

## 3. 踩坑记录

### 3.1 离散化后下标偏移

建筑 `[L, R, H)` 在离散化后覆盖的是**段索引**而非点索引。假设 points = [2, 10, 17]，则段为：
- 段 0: [2, 10)
- 段 1: [10, 17)

建筑 `[10, 17, 25]` 覆盖段索引 1，即 `[idx(10), idx(17) - 1]`。**右边界要减 1**。

### 3.2 线段树的"全覆盖短路"陷阱

当一个节点被全覆盖时，如果 `value[node] == -1`（子节点值不一致），不能直接覆盖该节点——子节点中可能有更高的值。

错误示例：节点 [3,4] 的子节点 [3,3]=25, [4,4]=0，因此 value = -1。新更新高度 14 全覆盖 [3,4]，如果直接设置 value = 14，则丢失了子节点中 25 的信息。

**修复**：全包含短路条件增加 `value[node] != -1`。

### 3.3 优先队列删除的坑

`PriorityQueue.remove(O)` 只删除一个副本。当多个同高度建筑重叠时，堆中会有多个副本。只调用一次 `remove` 无法全部删除，残留的副本会导致错误的高度残留。

**修复**：使用延迟删除（HashMap 计数），只在堆顶统一 prune。

### 3.4 同 x 事件的顺序

同一 x 上既有进入也有离开事件时，必须全部处理完再检查高度。**先处理所有事件再 prune + 检查**，无需在 x 内排序。

## 4. 技巧总结

### 延迟删除（Lazy Deletion）

当使用优先队列处理需要删除任意元素的场景时，`PriorityQueue` 不支持 O(log n) 的随机删除，用 HashMap 标记待删元素，堆顶统一弹出：

```java
// 标记删除
pending.put(height, pending.getOrDefault(height, 0) + 1);

// 统一清理堆顶
while (!pq.isEmpty() && pending.getOrDefault(pq.peek(), 0) > 0) {
    int h = pq.poll();
    pending.put(h, pending.get(h) - 1);
    if (pending.get(h) == 0) pending.remove(h);
}
```

该技巧同样用于 **480. 滑动窗口中位数**（双堆 + 延迟删除）。

> 相关笔记：[堆与优先队列.md](../经典解法/堆与优先队列.md)、[线段树.md](../经典解法/线段树.md)

### 区间覆盖中的"取 max"操作

与传统线段树的区间求和不同，天际线的更新是"取更高的值覆盖"。懒标记的使用方式也随之变化：
- 不是累加，而是取 max
- 用 -1 作为"子节点不一致"的哨兵
- 合并子节点时，左右相等才向上传递统一值

### 离散化 + 段索引

处理连续坐标问题时，将坐标点之间的"区间"作为基本单位（而非点本身），可以避免边界处理问题。

## 5. 思考过程

### 初始方向

首先想到差分，但差分适合累加型操作（如航班预订统计）。这里的"取更高的覆盖"不是累加，排除。

转向线段树：离散化 → 区间覆盖取 max → 最终遍历获取结果。

### 线段树的实现演化

**第一版**：直接 DFS 到每个叶子节点收集高度。这样做正确但效率较低（遍历全部叶子）。

**发现 unified 标记**：父节点可以记住"子节点是否一致"。当 `value[node] != -1` 时，说明整个区间高度统一，DFS 可直接返回，不必走到底。这就是方案2。

**bug：全覆盖短路误覆盖非统一节点**

测试 `[[2,13,10],[10,17,25],[12,20,14]]` 时发现结果错误。定位问题：节点 `[13, 17)` 的段被 building2 设为 25，节点值为 -1（因为相邻的 `[17, 20)` 段是 0）。building3 高度 14 全覆盖此区间时，`val > curVal(-1)` 条件通过，直接覆盖为 14，丢失了 25。

**修复**：全覆盖短路只在 `value[node] != -1` 时生效。对 -1 节点，必须 pushDown 递归到子节点逐一判断。

### 扫描线方案的讨论

扫描线方案更直接：只需排序事件 + 最大堆 + 延迟删除。但一开始想知道是否走线段树能走通，所以先实现了线段树。

**延迟删除的来源**：480.滑动窗口中位数 已经用过同样的模式（HashMap + prune），在 218 中直接复用。

### 两个方案的对比

| 方面 | 线段树 | 扫描线 + 优先队列 |
|------|--------|-----------------|
| 时间复杂度 | O(N log M) | O(N log N) |
| 实现复杂度 | 中等（离散化+线段树+DFS） | 简单（事件+堆+map） |
| 空间复杂度 | O(M) | O(N) |
| 适用场景 | 区间类问题通用，支持任意区间更新 | 专门针对"事件驱动"的扫描线 |

对于天际线问题，**扫描线+优先队列**是更优解——代码短、思路直、时间空间都好。但线段树解法展示了如何用区间数据结构处理"取 max 覆盖"操作，对后续类似问题（如 699.掉落的方块、850.矩形面积 II）有参考价值。
