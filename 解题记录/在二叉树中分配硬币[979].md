# 在二叉树中分配硬币 [979]

## 1. 解题思路

- **题目约束**：整棵树有 n 个节点，所有节点的硬币总数也恰好是 n，最终要让每个节点恰好有 1 枚硬币。**每次移动只能搬运 1 枚硬币**到相邻节点（父或子）。求最少移动次数。
- **核心难点**：硬币的流向是**双向**的——有的节点多了要送出去，有的节点缺了要收进来。直接模拟"谁往谁那送"会无从下手。
- **关键洞察：用"净流量"把双向化为一维**。把树沿任意一条边切开，分成"某一棵子树"与"它的外部"。此时：
  - 这棵子树最终需要的硬币数 = 它的节点数 N（每节点恰好 1 枚）；
  - 它现在拥有的硬币数 = 子树内所有节点 val 之和 S；
  - 二者的差 = **净盈余** = S - N。正数表示多出的硬币必须送出去，负数表示缺的必须收进来。

  **为什么净盈余的绝对值就是这条边的移动次数？**
  1. 硬币要进出这棵子树，**唯一能走的路就是"子树根与其父节点"之间那一条边**——没有别的出口。
  2. 题目规定一次只能搬 1 枚硬币，所以这条边**必须承载 |S - N| 次移动**，这是任何方案都绕不开的下界。
  3. 对每条边都算这个下界并累加，就是全局下界；而"按需调度"（子树多出的往外送、缺的往里补）可以恰好达到这个下界。
  4. **下界 = 最优**：因为硬币只能一步一步走边，每条边的必须穿越次数是确定且必然发生的，累计起来既是下界又可达到，所以就是最少移动次数。

- **算法选型**：后序遍历（树形 DP 的"自底向上合并"思想）。每个节点返回其子树的"总硬币数"和"总节点数"，父节点累加左右子树各自的净盈余绝对值。根节点没有父边，故根的盈余不累加。
- 复杂度：每个节点只访问一次，**O(n)** 时间，O(树高) 空间。

## 2. 代码实现

代码对应 `Algorithm-Cote/src/leetCode/moderately/DistributeCoins.java`：

```java
public class DistributeCoins {

    /** 全局计数器：累加每条边必须发生的移动次数 */
    int res = 0;

    public int distributeCoins(TreeNode root) {
        dfs(root);
        return res;
    }

    /**
     * 后序遍历：先递归算完左右子树，再汇总出以 node 为根的整棵子树的信息。
     *
     * @return int[2]：
     *         result[0] = 子树中所有节点硬币总数（含 node 自身 val）
     *         result[1] = 子树中节点总数（含 node 自身）
     */
    private int[] dfs(TreeNode node) {
        // 空节点：既没有硬币也没有节点
        if (node == null) {
            return new int[]{0, 0};
        }

        // 后序：先拿到左右子树的信息
        int[] l = dfs(node.left);
        int[] r = dfs(node.right);

        // 关键：净盈余 = 子树现有硬币数 - 子树需要的硬币数(节点数)
        // 左子树净盈余 = l[0] - l[1]，必须穿过 node 与左子之间的边，累加绝对值
        res += Math.abs(l[0] - l[1]);
        // 右子树净盈余 = r[0] - r[1]，必须穿过 node 与右子之间的边，累加绝对值
        res += Math.abs(r[0] - r[1]);

        // 汇总给父节点：总硬币数 = 自己 + 左 + 右；总节点数 = 1 + 左 + 右
        return new int[]{node.val + l[0] + r[0], 1 + l[1] + r[1]};
    }
}
```

**注意实现细节**：代码累加的是**左右子树**的净盈余绝对值，而不是 node 自身的——因为 node 自身的盈余要穿过"node 与其父节点"那条边，由父节点那层来累加。根节点没有父边，它的盈余自然永远不会被累加，正好正确。

## 3. 踩坑记录（若有）

- **误解一：以为一次可以搬运多枚硬币**。题目明确规定"每次移动只能移动一枚硬币"（move one coin per move），硬币必须一枚一枚走，这正是"净盈余绝对值 = 移动次数"的成立前提。若允许打包搬运，答案就会变成别的量。
- **误解二：父节点中转会"双倍计算"**。例如左子树盈余 +5 送到右子树（缺 5），路径为：左子 → 父（穿 1 条边，5 次）、父 → 右子（再穿 1 条边，5 次），共 10 次。这**不是重复计算**，而是每枚硬币真的跨过了两条边——移动次数与"路程"成正比，"每条边各算各的必须流量"天然覆盖了这种中转，不存在重复或遗漏。

## 4. 技巧总结

- **净流量 / 盈亏平衡思想**：当需求与供给在结构的两端时，不必模拟"谁给谁"，只算每一侧"多出来或缺多少"，绝对值就是必须穿越边界的流量。这是本题最核心的认知。
- **下界即最优（必然流量论证）**：想证明"最少"，可以先证明每条边有**必然发生的流量**（下界），再说明这个下界可达到，二者相等即得最优解。
- **树形 DP 后序汇总**：整棵树的答案依赖各子树的信息，用后序遍历自底向上合并，每个节点返回一个信息包，详见 [经典解法/树形DP.md](../经典解法/03-动态规划/树形DP.md)。
- 复杂度：O(n)。

## 5. 思考过程

- **最初的想法**：面对"双向流动"无从下手——节点可能多也可能少，不知道谁该往谁那送。
- **第一个疑惑（被引导解决）**：老师提示"把树沿一条边切开，看其中一侧"，发现只关心一侧的**净差值**（现有硬币数 − 节点数），双向问题立刻化为一维。
- **第二个疑惑**：净盈余好算，但它和"移动次数"有什么关系？——想通：硬币进出这棵子树只能走一条边，且一次只能搬一枚，所以这条边必须发生 |净盈余| 次移动。这是任何方案都绕不开的下界。
- **第三个疑惑（误解纠正）**：以为可以一次搬运多枚硬币（"盈余 5 一次性送走只算 1 次"）。被纠正：题目规定一次只能移动 1 枚。
- **第四个疑惑（误解纠正）**：以为"父节点中转会导致移动次数双倍"。用 A(+5)—父—B(−5) 的例子走一遍后想通：每枚硬币从 A 到 B 确实跨过两条边、产生 2 次移动，这是真实路程，不是重复计算；"每条边各算各的必须流量"恰好覆盖它。
- **认知转变**：本题不是"规划怎么搬"，而是"统计每条边必须搬多少次"。一旦意识到"下界 = 最优"，解法就从复杂的路径规划坍缩为一次简单的后序遍历。
