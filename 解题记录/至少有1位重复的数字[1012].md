# 至少有 1 位重复的数字 [1012]

## 1. 解题思路

### 问题描述

给定正整数 `n`，统计 `[1, n]` 中**至少有一位数字重复**的正整数个数。

**示例**：`n = 20`
- 范围：1, 2, 3, ..., 20
- 含重复数字：11
- 结果：1

### 核心难点

正面统计"至少有一位重复"的困难在于：**状态无法合并**。

若直接统计重复，需要在递归中传递每个数字的出现频次，因为后续路径需要知道前缀中哪些数字已用过、用了多少次，才能判断在新位置填某个数字后是否构成重复。但频次数组（int[10]）作为状态的话，不同前缀的状态完全不同，无法用 memo 缓存。

### 核心思路：补集转化

**至少一位重复 = 总数 − 所有位都不重复**

"所有位都不重复"是一个典型的数位DP问题：
- 只需要一个 10 位的 **bitmask** 记录哪些数字已被使用
- 状态空间 `O(len × 2¹⁰)` ≈ 40k，可 memo

**认识转变**：题目只关心"有没有重复"，而不是"每个数字出现了几次"。因此频次明细是过度的信息，bitmask 就足够刻画"无重复"状态。一旦发现有重复，直接剪枝即可——因为补集只统计无重复的数字。

### 状态设计

| 参数 | 含义 | 初始值 | 传递逻辑 |
|------|------|--------|----------|
| `cur` | 当前处理到的数位下标（高位到低位，0-indexed） | 0 | `cur + 1` |
| `bitMask` | 已使用数字的 bitmask（第 k 位=1 表示数字 k 已用过） | 0 | 非前导零时 `bitMask \| (1 << i)` |
| `isLimit` | 之前各位是否都与 n 的前缀一致 | `true` | `isLimit && (i == up)` |
| `leadZero` | 是否仍在处理前导零 | `true` | `leadZero && (i == 0)` |

### 终止条件

当 `cur == nums.length`（所有位处理完毕）：
- 若仍处于前导零状态 → 代表数字 0，不在 `[1, n]` 范围内，不计入
- 否则构造出一个合法数字 → 返回 1

### 递推逻辑

```
dfs(cur, bitMask, isLimit, leadZero):
    出口：cur == len → return leadZero ? 0 : 1
    
    up = isLimit ? nums[cur] : 9
    res = 0
    枚举 i = 0..up:
        if bitMask 第 i 位为 1 → continue  // 重复，剪枝
        nextMask = (leadZero && i == 0) ? bitMask : (bitMask | (1 << i))
        res += dfs(cur+1, nextMask, isLimit && (i == up), leadZero && (i == 0))
    写入缓存（仅在 !isLimit && !leadZero 时）
    return res
```

**前导零的 mask 处理**：当 `leadZero && i == 0` 时，这个 0 只是前导占位符，不代表真正使用数字 0，因此 mask 保持不变。

### 最终结果

```
结果 = n - dfs(0, 0, true, true)
```

因为 dfs 的 base case 已排除数字 0，`dfs(0, 0, true, true)` 直接返回 `[1, n]` 中无重复数的个数，用 `n` 减去即得答案。

## 2. 代码实现

```java
public class NumDupDigitsAtMostN {

    int[][] memo;
    int[] nums;

    public int numDupDigitsAtMostN(int n) {
        int[] temp = new int[32];
        int length = 0, t = n;
        while (t > 0) {
            temp[length++] = t % 10;
            t /= 10;
        }
        nums = new int[length];
        for (int i = length - 1; i >= 0; i--) {
            nums[i] = temp[length - 1 - i];
        }
        memo = new int[length][1 << 10];
        for (int i = 0; i < length; i++) {
            Arrays.fill(memo[i], -1);
        }
        return n - dfs(0, 0, true, true);
    }

    int dfs(int cur, int bitMask, boolean isLimit, boolean leadZero) {
        if (cur == nums.length) {
            return leadZero ? 0 : 1;
        }
        if (!isLimit && !leadZero && memo[cur][bitMask] != -1) {
            return memo[cur][bitMask];
        }
        int up = isLimit ? nums[cur] : 9;
        int res = 0;
        for (int i = 0; i <= up; i++) {
            if ((bitMask & (1 << i)) != 0) {
                continue;
            }
            int nextMask = (leadZero && i == 0) ? bitMask : (bitMask | (1 << i));
            res += dfs(cur + 1, nextMask, isLimit && (i == up), leadZero && (i == 0));
        }
        if (!isLimit && !leadZero) {
            memo[cur][bitMask] = res;
        }
        return res;
    }
}
```

## 3. 踩坑记录

### 踩坑 1：memo 数组第二维大小错误

最初将 memo 声明为 `new int[length][1]`，认为"一个 int 就够了"。但 bitMask 取值范围是 `0~1023`（10 位二进制），访问 `memo[cur][bitMask]` 时第二维下标超出范围，导致 `ArrayIndexOutOfBoundsException`。

**修复**：`new int[length][1 << 10]`

### 踩坑 2：前导零误标记 mask

当 `leadZero` 为 true 且当前枚举数字 `i = 0` 时，这个 0 只是前导占位符（如数字 `05` 实际上代表 5），不应该在 mask 中标记数字 0 已被使用。否则会导致全零路径（代表数字 0）被错误拦截，且某些路径可能因 mask 标记了不该标记的 0 而少计数。

**修复**：使用条件判断 `(leadZero && i == 0) ? bitMask : (bitMask | (1 << i))`

### 踩坑 3：数字 0 的处理

补集递归的 base case 直接返回 1 的话，全前导零路径（代表数字 0）会被计入。但问题范围是 `[1, n]`，0 应被排除。若 dfs 包含了 0，最终公式需调整为 `n - dfs + 1`。

**修复**：base case 返回 `leadZero ? 0 : 1`，直接让 dfs 不包含 0，使 `n - dfs` 保持语义正确。

## 4. 技巧总结

- **补集转化**：当正面直接统计条件复杂（状态多、无法合并）时，考虑统计它的补集，再用总数减去。"至少一位重复" → "所有位都不重复"
- **bitmask 代替频次数组**：当条件只需知道"有没有"而非"有多少次"时，10 位 bitmask 比 int[10] 数组更轻量、更易缓存
- **前导零的精细处理**：前导 0 不占用数字 0 的资源，mask 不应标记前导 0
- **base case 直接排除边界值**：在递归出口处理范围边界（如本题的 0），比最终用公式补偿更直观、不易出错
- **数位DP的状态压缩思想**：`!isLimit && !leadZero` 时，后续子问题只依赖于 `(cur, bitMask)`，两个布尔参数不用进缓存键——这是数位DP记忆化的核心规律

## 5. 思考过程

**最初的理解**：看到"至少一位重复"，立刻想到数位DP框架。但直觉上认为需要在递归过程中统计每个数字的出现频次，因此想用一个 int[10] 数组作为状态向下传递，并在每一层判断是否有重复。

**遇到的困惑**：如果返回频次数组，那么多叉分支返回的频次无法合并——不同分支路径不同，频次不同，不能简单累加。如果改成自顶向下传频次，那 memo 没法缓存，因为每个前缀的频次都不相同。

**关键转折点**：意识到"至少一位重复"的补集是"所有位都不重复"。后者只需一个 bitmask 记录哪些数字已用过即可，状态空间小（10 位二进制），可以 memo。这相当于把"知道每个数字出现几次"降维成"知道每个数字有没有出现过"。

**最终确认**：用补集 + 标准数位DP模板，实现很简洁。三个初始编写的小 bug（memo 大小、前导 0 标记、base case 排除 0）排查后全部修复，一次跑通。

**认知转变**：补集转化在计数类问题中非常强大。正面看似复杂的状态，反面可能非常简单。关键在于识别"题目真正关心的信息粒度"——这里只关心"有没有重复"，不关心"重复了多少次"。
