# 不含连续1的非负整数 [600]

## 1. 解题思路

### 问题描述

给定正整数 `n`，统计 `[0, n]` 中所有**二进制表示不含连续 1** 的数字个数。

**示例**：`n = 5`（二进制 `101`）
- 范围：0 (0), 1 (1), 2 (10), 3 (11), 4 (100), 5 (101)
- 3 (11) 含连续 1 → 排除
- 5 (101) 不含连续 1 → 保留
- 结果：5 个（0, 1, 2, 4, 5）

### 核心难点与思路

题目要求二进制层面的条件，**二进制本身也是数位，只不过每位取值从十进制的 0~9 变为二进制的 0/1**。数位DP的框架完全适用，只需做两点调整：

1. **进制转换**：将 n 转为二进制位数组（高位到低位），枚举范围从 `0~9` 变为 `0~1`
2. **增加 `prev` 状态**：记录上一位的值，当前位与上一位不能同时为 1

**核心认识**：数位DP不局限于十进制，任何进制都可以——参数 `limit`、`leadZero`、`pos` 的语义完全不变，唯一变化的是 `up` 的上界。

### 状态设计

| 参数 | 含义 | 初始值 | 传递逻辑 |
|------|------|--------|----------|
| `index` | 当前处理到的二进制位下标（高位到低位，0-indexed） | 0 | `index + 1` |
| `last` | 上一位的值（0 或 1），用于检测连续 1 | 0（前导 0 状态的安全默认值） | 当前位 `i` |
| `limit` | 之前各位是否都与 n 的前缀一致 | `true` | `limit && (i == up)` |
| `leadZero` | 是否仍在处理前导零 | `true` | `leadZero && (i == 0)` |

**为什么 `last` 初始为 0 是安全的？**

当 `leadZero=true` 时，所有的前导 0 并不代表实际的二进制位，此时 `last` 始终为 0。若枚举 `i=1`，`leadZero` 变为 `false`，`last` 变为 1——这是合法的（前导 0 后面可以跟 1）。若枚举 `i=0`，维持 `leadZero=true`，`last=0` 也不影响后续判断。因此 `last=0` 在前导 0 阶段只是一个无害的默认值。

### 终止条件

当 `index == nums.length`（所有位处理完毕），构造出了一个完整数字，返回 `1`。

### 递推逻辑

```
dfs(index, last, limit, leadZero):
    出口：index == len → return 1
    
    up = limit ? nums[index] : 1
    res = 0
    枚举 i = 0..up:
        if (i == 1 && last == 1) → continue  // 连续1，跳过
        res += dfs(index+1, i, limit&&i==up, leadZero&&i==0)
    写入缓存（仅在 !limit && !leadZero 时）
    return res
```

### 缓存设计：为什么只需要 `memo[index][last]`？

这是本题最值得思考的设计点。

**缓存条件**：`!limit && !leadZero`

在此条件下，后续子问题只依赖两个信息：
1. **还剩多少位**（由 `index` 决定）
2. **上一位的值**（由 `last` 决定）

`last` 之所以够用，是因为：
- 二进制每一位只有 0 或 1，只需知道上一位的值即可判断当前位能否放 1
- 上一位的值唯一决定了后续可选集合：若 `last=1`，当前位只能选 0；若 `last=0`，当前位可选 0 或 1
- 不需要更早的位的值——**连续 1 的判断只涉及相邻两位**

对比十进制数位DP（如 233. 数字1的个数），那里需要缓存 `[index]`，因为条件（统计 1 的个数）不依赖相邻位，靠递归聚合即可。这里条件依赖相邻位，因此需要额外一维 `last`——但仅此而已，不需要更多历史信息。

**一个直觉**：如果把所有合法数字看成 Trie 树（根为最高位），那么 `(index, last)` 唯一确定了 Trie 的一个子树。`!limit && !leadZero` 意味着这个子树的根已经固定，后面的所有分支完全相同，可以缓存。

### 二进制 vs 十进制：两条等价路径

这是一个很重要的视角：数位DP的"数位"可以是任何进制。

| 维度 | 十进制数位DP | 二进制数位DP（本题） |
|------|-------------|-------------------|
| 每位取值范围 | 0~9 | 0~1 |
| 位数长度 | log₁₀(n) | log₂(n) |
| limit 控制 | 上界 n 的十进制位 | 上界 n 的二进制位 |
| leadZero | 前导 0 不影响数值大小 | 同左 |
| 缓存条件 | `!limit && !leadZero` | 同左 |
| 业务状态 | 按需（如统计 1 则不需要额外维度） | `last`（上一位的值） |

二者共享同一套模板，只是进制的不同实例化。

## 2. 代码实现

```java
public class FindIntegers {

    /** memo[i][j] = 当前第i位、上一位为j时，后续的有效元素个数 */
    int[][] memo;
    /** n 的二进制表示（高位到低位） */
    int[] nums;

    public int findIntegers(int n) {
        if (n == 0) return 1;

        // 将 n 转为二进制位数组
        int[] temp = new int[32];
        int length = 0, t = n;
        while (t > 0) {
            temp[length++] = t & 1;
            t >>= 1;
        }
        nums = new int[length];
        for (int i = length - 1; i >= 0; i--) {
            nums[i] = temp[length - 1 - i];
        }

        memo = new int[length][2];
        for (int i = 0; i < length; i++) {
            Arrays.fill(memo[i], -1);
        }

        return dfs(0, 0, true, true);
    }

    int dfs(int index, int last, boolean isLimit, boolean leadZero) {
        if (index == nums.length) return 1;

        if (!isLimit && !leadZero && memo[index][last] != -1) {
            return memo[index][last];
        }

        int up = isLimit ? nums[index] : 1;
        int res = 0;
        for (int i = 0; i <= up; i++) {
            if (i == 1 && last == 1) continue;  // 连续1，跳过
            res += dfs(index + 1, i,
                    isLimit && i == up,
                    leadZero && i == 0);
        }

        if (!isLimit && !leadZero) {
            memo[index][last] = res;
        }
        return res;
    }
}
```

## 4. 技巧总结

- **数位DP不限于十进制**：`limit`、`leadZero`、`pos` 三件套适用于任意进制，只需调整每一位的取值范围
- **状态压缩的思路**：二进制每一位只有 0/1，连续 1 的判断只需记住上一位，因此 `memo[pos][last]` 足够，状态空间仅 `log₂(n) × 2`
- **前导 0 不影响相邻位判断**：前导 0 阶段的安全默认值设 0 即可，不会误拦合法分支
- **记忆化搜索的边界**：只有 `!limit && !leadZero` 才写缓存，缓存键只包含真正影响子问题的维度

## 5. 思考过程

这是我做的第二道数位DP题（前一道是 233. 数字1的个数）。

**最初的直觉**：看到"不含连续1"和二进制，立刻想到标准数位DP框架。核心变化是将十进制位（0~9）换成二进制位（0~1），两者本质相同。

**遇到的考量点**：
- 缓存需要什么维度？因为条件涉及相邻位，所以需要记录 `last` 作为第二维。但二进制只有 0/1，`last` 只需要 2 个取值即可，不需要像十进制那样有 10 种可能性
- `leadZero` 和 `last` 的交互：前导 0 阶段 `last` 设 0 是否安全？分析后发现安全——因为前导 0 阶段只能选 0 来维持 `leadZero`，`last` 保持 0；一旦选了 1，`leadZero` 消失，`last` 正确更新

**最终确认**：整个框架与十进制的数位DP完全一致，只是二进制位数更短（log₂(n) vs log₁₀(n)）、状态空间更小。没有碰到意料之外的坑，很顺畅地完成了实现。

**关键认知转变**：数位DP的"数位"本身是一种抽象——任何进制都可以套用，核心参数 `limit`、`leadZero`、`pos` 不变，变的只是枚举范围和业务状态。
