# 石子游戏 VI [1686]

## 1. 解题思路

**问题**：`aliceValues[i]` 和 `bobValues[i]` 分别是 Alice / Bob 对第 i 块石头的**主观价值**。两人轮流取走一块石头，各自得分 = 自己拿到的石头上**自己视角的价值**之和。Alice 先手。判断谁得分更高。

**核心难点**：这不是博弈 DP——没有"取法影响后续局面"的相互纠缠，本质是**排序贪心**。难点在于想清楚排序键。

**关键洞察**：Alice 拿走石头 `i` 时，不仅自己得到 `aliceValues[i]`，还**让 Bob 失去**潜在的 `bobValues[i]`。所以一块石头的"战略价值"是：

```
aliceValues[i] + bobValues[i]
```

**用交换论证推导排序键**：设剩下两块石头 `i` 和 `j`，Alice 先拿。

- 情况 1：Alice 拿 `i`，Bob 拿 `j` → Alice 领先 `a[i] − b[j]`
- 情况 2：Alice 拿 `j`，Bob 拿 `i` → Alice 领先 `a[j] − b[i]`

Alice 希望情况 1 更好：

```
a[i] − b[j] ≥ a[j] − b[i]
⟺ a[i] + b[i] ≥ a[j] + b[j]
```

所以**排序键是 a+b（两人的"和"）**，而不是"差"。按 `a+b` 降序排列后：

- Alice 先手拿**偶数位**（0, 2, 4...，即战略价值最大的那些）
- Bob 拿**奇数位**（1, 3, 5...）

最后各自累加**真实价值**比较：`alice > bob → 1`，`alice < bob → -1`，相等 → 0。

## 2. 代码实现

```java
package leetCode.moderately;

import java.util.Arrays;

/**
 * @description: 1686. 石子游戏 VI
 *
 * 思路：排序贪心（非博弈DP）。Alice 拿走石头 i 时，不仅得到 aliceValues[i]，
 * 还让 Bob 失去潜在的 bobValues[i]，所以一块石头的"战略价值" = aliceValues[i] + bobValues[i]。
 * 按 a+b 降序排列，Alice 先手拿偶数位，Bob 拿奇数位，最后比较得分。
 * 复杂度：排序 O(n·log n)，空间 O(n)。
 */
public class StoneGameVI {

    /**
     * 排序贪心：判断 Alice 与 Bob 谁得分高
     *
     * 算法：按 aliceValues[i]+bobValues[i] 降序排列下标，Alice 拿偶数位、Bob 拿奇数位，
     * 累加各自真实价值后比较返回。
     *
     * 踩坑记录：
     * 1. 排序键写错：曾用 a-b（相对收益）做排序键，正确应为 a+b（战略价值）。
     *    因为 Alice 拿走石头 i 的同时也让 Bob 失去 b[i]，交换论证可得排序键是"和"而非"差"。
     * 2. 排序后丢索引：若直接对 sum=a+b 数组排序，则累加时无法还原对应的 a 和 b。
     *    必须对下标数组排序，再用下标取回真实价值。
     * 3. 排序方向写反：comparingInt 默认升序，位置 0 是最小值；需要降序（位置 0 为最大值），
     *    否则 Alice 先手拿到的是战略价值最小的石头。
     * 4. 倒序遍历奇偶错位：把循环改成 i 从 n-1 递减后，若仍用 i%2 判断归属，
     *    当 n 为偶数时最大的石头会被判给 Bob。正序遍历（位置 0 最大）奇偶归属才正确。
     * 5. 返回值类型：题目要求返回 int（1=Alice 胜 / -1=Bob 胜 / 0=平局），
     *    不要误写成字符串 "Alice"/"Bob"/"Tie"。
     *
     * @param aliceValues Alice 对每块石头的主观价值
     * @param bobValues   Bob 对每块石头的主观价值
     * @return 1 表示 Alice 得分更高，-1 表示 Bob 得分更高，0 表示平局
     */
    public int stoneGameVI(int[] aliceValues, int[] bobValues) {
        int n = aliceValues.length;
        Integer[] idx = new Integer[n];
        for (int i = 0; i < n; i++) {
            idx[i] = i;
        }
        // 按 a+b 降序排列：位置 0 是战略价值最大的石头，Alice 先手拿偶数位
        Arrays.sort(idx, (x, y) -> (aliceValues[y] + bobValues[y]) - (aliceValues[x] + bobValues[x]));
        int alice = 0, bob = 0;
        for (int i = 0; i < n; i++) {
            if (i % 2 == 0) {
                alice += aliceValues[idx[i]];
            } else {
                bob += bobValues[idx[i]];
            }
        }
        if (alice > bob) {
            return 1;
        } else if (alice < bob) {
            return -1;
        }
        return 0;
    }
}
```

## 3. 踩坑记录

这道题是石子游戏系列里最容易"栽在细节"的一题，踩坑点远比算法本身多：

- **排序键选错（最核心）**：最初直觉用"差"（`a−b`）做相对收益排序。正确排序键是**"和"**（`a+b`）。原因：Alice 拿走石头还抢走了 Bob 的潜在价值，交换论证证明排序键必须是和。
- **排序丢索引**：第一版直接对 `sum = a+b` 数组排序，累加时用 `sum[i]` 当得分——既丢了 a/b 的对应关系，又把"战略价值"当成了"得分"。必须排序**下标数组**，再取回真实价值。
- **排序方向写反**：`comparingInt` 默认升序，位置 0 是最小值。Alice 先手必须拿最大的，要降序。
- **倒序遍历的奇偶错位**：尝试改从 `n-1` 倒序遍历来"拿大的"，但奇偶判断仍用 `i % 2`，当 n 为偶数时位置 `n-1`（最大的石头）`i%2==1` 被判给 Bob。必须正序遍历（位置 0 最大）。
- **返回值类型**：题目要求 `int`（1/-1/0），误以为返回字符串 "Alice"/"Bob"/"Tie"。

## 4. 技巧总结

- **博弈题先判断是否真的是博弈**：若行动不产生相互影响的"状态传递"（无后续局面），往往不是 DP 而是贪心/排序。判断标准：**轮到某人时剩余局面的"价值函数"是否被上一步改变**。本题两人只是分走一堆各自价值不同的石头，等价于"分赃"，排序即可。
- **"拿一块 = 自己得 + 对方失"**：当同一资源对双方价值不同时，决策排序键是 `我拿到的 + 对方失去的`，交换论证是通用证明工具。
- **排序贪心的通用写法**：对**下标数组**排序（保留原索引），别对值本身排序；注意升降序方向；遍历时用"排序后位置"决定归属。
- 对比同系列：877 是奇偶分组 O(1)、1140/1406 是博弈 DP、1510 是必胜态布尔 DP、1563 是区间 DP——**1686 是唯一纯排序贪心**，说明"石子游戏"系列覆盖了极多不同的解法形态。

## 5. 思考过程

本次学习基于与 agent 的对话完成：

1. **初始判断正确**：一眼看出没有"从两端取"的限制，结构简单，应是贪心排序而非 DP。这个判断方向是对的。
2. **排序键的第一个误区**：最初想用"两人的收益做差形成相对收益数组"排序。被引导做交换论证后才发现，排序键是 `a+b` 而非 `a−b`——因为忽略了"拿走的同时让对手失去"这一层。这是认知转变的关键点。
3. **实现连环踩坑**：排序丢索引 → 排序方向反 → 倒序遍历奇偶错位，共四个实现 bug。每一处都是"排序+索引"这一类题目的经典陷阱，靠官方示例对拍逐一暴露。
4. **教训总结**：排序贪心题（尤其涉及双人/多属性排序）要按固定套路写：下标数组 + 明确升降序 + 排序后位置定归属，缺一不可。
