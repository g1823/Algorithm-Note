# 打家劫舍 III [337]

## 1. 解题思路

- **核心难点**：父子节点不能同时被偷，父节点的最优决策取决于"子节点是否被偷"，单一 dp 状态无法表达这种制约关系。
- **算法选型**：树形 DP。将问题拆成"以每个节点为根的子树"，利用最优子结构（子树独立、互不影响）自底向上合并。
- **状态设计**：每个节点维护两个状态——
  - 偷当前节点：左右子节点都不能偷；
  - 不偷当前节点：左右子节点各自取"偷/不偷"的较优者再累加。
- **遍历方式**：后序遍历。必须先递归算完左右子树，父节点才能拿到子节点的两种状态做合并。

## 2. 代码实现

代码对应 `Algorithm-Cote/src/leetCode/moderately/Rob3.java`：

```java
public class Rob3 {
    public static void main(String[] args) {
        TreeNode root = new TreeNode(2);
        TreeNode node1 = new TreeNode(1);
        TreeNode node2 = new TreeNode(3);
        TreeNode node3 = new TreeNode(4);
        root.left = node1;
        root.right = node2;
        node1.right = node3;
        System.out.println(new Rob3().rob2(root));
    }

    /**
     * 树形 DP 入口：返回根节点"偷/不偷"两种状态的最大值
     */
    public int rob2(TreeNode root) {
        int[] result = dfs2(root);
        return Math.max(result[0], result[1]);
    }

    /**
     * 后序 DFS：先算左右子树，再合并出当前节点状态
     *
     * @return int[2]：
     *         result[0] = 偷 node 时，以 node 为根的子树最高金额
     *         result[1] = 不偷 node 时，以 node 为根的子树最高金额
     */
    public int[] dfs2(TreeNode node) {
        // 边界：空节点偷与不偷都是 0
        if (node == null) return new int[]{0, 0};

        // 后序：先递归算完左右子树
        int[] leftResult = dfs2(node.left);
        int[] rightResult = dfs2(node.right);

        // 偷 node：左右子节点都不能偷，只能取各自"不偷"状态
        int steal = node.val + leftResult[1] + rightResult[1];
        // 不偷 node：左右子节点偷或不偷都可以，各自取更优再累加
        int notSteal = Math.max(leftResult[0], leftResult[1])
                     + Math.max(rightResult[0], rightResult[1]);

        return new int[]{steal, notSteal};
    }
}
```

## 3. 踩坑记录

- **数组下标语义要统一**：返回值 `[0]` 表示偷、`[1]` 表示不偷，转移时容易写反（如偷 node 却错误地加上子节点的"偷"状态）。建议用 `steal` / `notSteal` 命名消除歧义。
- **初始错误理解**：曾试图用深度优先 + 数组记录每条路径上的最优值（`rob` 方法），但路径之间会共用节点、互相影响，无法表达"整棵树"的全局最优，必须换成"以子树为单位"的树形 DP。

## 4. 技巧总结

- **树形 DP 核心套路**：后序遍历 + 子节点状态合并成父节点状态，详见 [经典解法/树形DP.md](../经典解法/03-动态规划/树形DP.md)。
- **状态拆分判断**：当父节点决策依赖"子节点是否被选中"时，必须拆分多种互斥状态。
- **复杂度**：O(n)，每个节点只访问一次。

## 5. 思考过程

- 最初的想法是"树形 DP 就是记忆化递归的变体"，把 DFS 遍历和 DP 数组同时进行。
- 与 agent 讨论后纠正：树形 DP 的关键是**后序合并**，子问题就是子树，树无环 → 不存在重叠子问题 → 不需要记忆化。
- 进一步想通了状态设计：为什么 dp[u] 一个值不够？因为父节点偷/不偷，子节点的可选范围不同，父节点必须知道子节点"是否被偷"这个信息，所以每个节点要维护两种状态。
- 最终通过 337 把"状态拆分"和"后序合并"两个核心点串起来，形成对树形 DP 的整体认知。
