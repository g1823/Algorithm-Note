# 监控二叉树 [968]

## 1. 解题思路

- **核心难点**：一个摄像头能覆盖**自身、父节点、直接子节点**三层。要判断某个节点是否被覆盖，必须知道"谁覆盖了它"——可能是自己装、父节点装、或子节点装。单靠一个 dp 值无法表达这种**覆盖来源**的制约关系。
- **状态设计**：用两个维度（**是否有摄像头** + **是否被覆盖**）穷举出三种互斥状态：
  - `0` = 该节点**有摄像头**
  - `1` = 该节点**被覆盖**（没摄像头，被父或子覆盖）
  - `2` = 该节点**未覆盖**（没摄像头，也没被覆盖，等待父节点来救）
- **遍历方式**：后序遍历。父节点的状态依赖子节点状态，必须先递归算完子树再自底向上合并。
- **算法选型**：两条路线，最终答案一致——
  - **路线 A（树形 DP）**：每节点返回 3 个值，穷举所有合法组合，严谨但不简洁；
  - **路线 B（贪心压缩）**：证明三态中"其他两个状态要么非法、要么被支配"，压缩为每节点只返回 1 个状态 + 全局计数，代码极简。

## 2. 代码实现

代码对应 `Algorithm-Cote/src/leetCode/difficult/MinCameraCover.java`，包含两种解法：

```java
public class MinCameraCover {

    // ==================== 解法一：树形 DP（返回三状态） ====================

    /**
     * 状态定义（返回数组下标）：
     * [0] = 该节点有摄像头时，子树最小摄像头数
     * [1] = 该节点被覆盖（没摄像头）时，子树最小摄像头数
     * [2] = 该节点未覆盖（没摄像头）时，子树最小摄像头数
     *
     * 转移方程（l、r 为左右子树的三态数组）：
     * i0 = 1 + min(l) + min(r)   自己装，孩子任意状态都合法
     * i1 = min(l[0]+r[0], l[0]+r[1], l[1]+r[0])
     *                             被覆盖，至少一个孩子有摄像头；
     *                             另一孩子只能是 [0] 或 [1]（若是 [2]，自己没装救不了它）
     * i2 = l[1] + r[1]           未覆盖，孩子必须全被覆盖且都没装摄像头
     */
    public int minCameraCover(TreeNode root) {
        int[] res = dfs(root);
        // 根节点没有父节点，若处于"未覆盖"则无人可救，只能取 [0] 或 [1]
        return Math.min(res[0], res[1]);
    }

    private int[] dfs(TreeNode node) {
        if (node == null) {
            // 空节点返回 (INF, 0, 0)：
            // [0]=INF 空节点不存在"有摄像头"，返回 0 等于白送免费摄像头（反例：单节点树）；
            //        注意不能取 Integer.MAX_VALUE，两个 INF 相加溢出成负数会被 min 选中。
            // [1]=0 / [2]=0 空节点不贡献摄像头数（叶子 dp2 = 0+0 = 0 依赖此值）。
            return new int[]{Integer.MAX_VALUE / 2, 0, 0};
        }
        int[] l = dfs(node.left);
        int[] r = dfs(node.right);
        int i0 = 1 + minOf(l) + minOf(r);   // 自己装：孩子任意状态，各自取最小
        int i1 = Math.min(
                l[0] + r[0],                 // 左、右都装
                Math.min(l[0] + r[1],        // 左装、右被覆盖
                         l[1] + r[0]));      // 右装、左被覆盖
        int i2 = l[1] + r[1];                // 孩子全被覆盖且都没装
        return new int[]{i0, i1, i2};
    }

    private int minOf(int[] state) {
        return Math.min(state[0], Math.min(state[1], state[2]));
    }

    // ==================== 解法二：贪心压缩（单状态） ====================

    /**
     * 贪心依据：摄像头越往上放越"赚"——父节点装能覆盖自身+父+两个子，
     * 叶子装只能覆盖自身+父。所以每层都"尽量不装、把压力上推"，
     * 只有在孩子未覆盖、非装不可时才被迫装。
     */
    class Solution2 {
        int res = 0;

        public int minCameraCover(TreeNode root) {
            int status = dfs(root);
            if (status == 2) {   // 根未覆盖：没有父节点可救，只能自己装
                res++;
            }
            return res;
        }

        /**
         * 返回当前节点状态：0=有摄像头 1=被覆盖 2=未覆盖
         */
        private int dfs(TreeNode node) {
            if (node == null) {
                return 1;   // 空节点视为"被覆盖"，不麻烦父节点（叶子才能正常返回 2）
            }
            int l = dfs(node.left);
            int r = dfs(node.right);
            if (l == 2 || r == 2) {        // 孩子未覆盖 → 必须装，计数+1
                res++;
                return 0;
            }
            if (l == 1 && r == 1) {        // 孩子全被覆盖 → 裸着，压力甩给父节点
                return 2;
            }
            // 有孩子装了摄像头且无未覆盖 → 当前节点被覆盖
            return 1;
        }
    }
}
```

复杂度：两种解法均为 O(n) 时间、O(树高) 空间。

## 3. 严格证明（贪心 = DP 压缩的正确性）

DP 已穷举所有合法组合，是最优的。要证明贪心正确，只需证明**贪心返回的状态 = DP 三态中的最小值对应状态**，用后序遍历归纳：

> **归纳命题**：贪心处理完以 X 为根的子树返回 `(s, c)`，则 `dp_s[X] = c`，且 s 是 X 三态中最小值对应的状态。

（空节点返回 `(2, 0)`：dp2=0 是 `(INF,0,0)` 中最小，奠基成立。）

### 情况一：有孩子返回 2（未覆盖）→ X 返回 0

- **必要性**：返回 2 的孩子没装摄像头、也没被孙子覆盖，它的覆盖来源只剩父节点 X → X **必须装**，其他两个状态非法。
- **最优性**：X 装后孩子任意状态皆合法，取各自最小值即 `dp0[X] = 1 + cL + cR`。唯一合法，自然最优。

### 情况二：孩子全返回 1（都被覆盖）→ X 返回 2

- `dp2[X] = l[1] + r[1] = cL + cR` ✓
- `dp0[X] = 1 + cL + cR > c`：孩子都被覆盖了，X 再装是**纯浪费**，被支配。
- `dp1[X] = min(l[0]+r[0], l[0]+r[1], l[1]+r[0])`：孩子返回 1 蕴含 `l[1] ≤ l[0]`、`r[1] ≤ r[0]`，三个组合都 ≥ `l[1]+r[1] = c`，被支配或持平。
- 结论：**dp2 最小**，返回 2 正确。

### 情况三：无 2、有孩子返回 0（有摄像头）→ X 返回 1

- `dp1[X]`：取"0 孩子 + 另一孩子最小"的组合即可达 `cL + cR` ✓
- `dp0[X] = 1 + cL + cR > c`。
- `dp2[X] = l[1] + r[1] ≥ c`（返回 0 的孩子 `l[1] ≥ dp0 = cL`），被支配。
- 结论：**dp1 最小**，返回 1 正确。

### 根的特判

根返回 2 时（孩子全 1）需补装 `+1`。需证 `dp0[root] ≤ dp1[root]`：

- 返回 1 的孩子满足 `dp0 > dp1`（情况三中 dp0 被支配，严格大于）；
- 故 `dp1[root] ≥ 1 + cL + cR = dp0[root]`，根的答案 `min(dp0, dp1) = dp0`，与补装结果一致 ✓

### 分支穷举：三种 if 覆盖全部 9 种组合

| (l, r) | 命中分支 | 返回 | 语义 |
|:------:|:--------:|:----:|------|
| (0,0) | ③ 有 0 | 1 | 孩子都装，自己被覆盖 |
| (0,1) | ③ 有 0 | 1 | 左装右覆盖，自己被覆盖 |
| (0,2) | ① 有 2 | 0 | 右未覆盖 → 必须装 |
| (1,0) | ③ 有 0 | 1 | 右装左覆盖，自己被覆盖 |
| (1,1) | ② 全 1 | 2 | 孩子都被覆盖 → 裸着甩给父 |
| (1,2) | ① 有 2 | 0 | 右未覆盖 → 必须装 |
| (2,0) | ① 有 2 | 0 | 左未覆盖 → 必须装 |
| (2,1) | ① 有 2 | 0 | 左未覆盖 → 必须装 |
| (2,2) | ① 有 2 | 0 | 都未覆盖 → 必须装 |

> 分支顺序安全：①先拦所有含 2 的组合（必须装），②再拦全 1（裸着上推），③最后收掉含 0 且无 2 的组合（被覆盖）。9 种组合无遗漏，因此解法二代码末尾的兜底 `return 1;` 实际永不执行，仅满足 Java 编译要求。

## 4. 踩坑记录

- **INF 溢出成负数**：空节点若取 `Integer.MAX_VALUE` 作无穷大，`dp1` 中两个 INF 相加会溢出成负数，反被 `min` 选中导致结果全错（单节点树算出 -2）。改用 `Integer.MAX_VALUE / 2` 保证两个 INF 相加不溢出。
- **空节点 `[0]` 不能取 0**：若空节点"有摄像头"返回 0，等于白送一个免费摄像头，单节点树会被错误判定为"根被覆盖，答案 0"，而正确答案是 1。
- **dp1 转移最初写错**：误写成 `min(dpl[0]+dpr[0], dpl[0], dpr[0])`，漏掉了"左装右被覆盖 `l[0]+r[1]`、右装左被覆盖 `l[1]+r[0]`"两种组合。用反例纠正：X 的两个叶子孩子都装才满足"X 被覆盖"，答案应为 2 而非误算的 1。
- **文件被还原的坑**：调试中发现代码文件被改回溢出版本（`Integer.MAX_VALUE`），暴力验证结果全是负数。**每次改动后应重新确认磁盘上源码是期望版本**，再编译验证。
- **编译缓存/编码坑**：Windows 下 javac 可能复用旧 `.class`；测试文件含 BOM 会导致 JDK8 编译报"非法字符"，需去除 BOM。

## 5. 技巧总结

- **树形 DP 状态拆分**：当父节点决策依赖"子节点是否被选 / 是否被覆盖"时，必须拆成多种互斥状态，详见 [经典解法/树形DP.md](../经典解法/03-动态规划/树形DP.md)。
- **覆盖类问题三状态模板**：`有摄像头 / 被覆盖 / 未覆盖`，其中"未覆盖"本质是**向上传递压力**的信号，而"被覆盖"是**信号终止**（父节点不用管我）。
- **DP 压缩为贪心的判定**：当某种状态下，其余状态要么**非法**、要么**被支配**（严格更差）时，三态可坍缩为单状态 + 全局计数。
- **交叉验证法**：遇到拿不准的 DP，可写暴力枚举（穷举所有放置方案）与小规模随机树交叉验证，能快速定位 bug。
- 复杂度：O(n)。相关：该题是 [贪心法](../算法思想/贪心法.md) 在树形覆盖问题上的典型应用。

## 6. 思考过程

- **最初的想法**："不可连续三级没有摄像头"，认为记录两种状态（自己装 / 子级装）就够。
- **第一个疑惑**：叶子节点既没装也没孩子覆盖，处在什么状态？—— 发现需要第三种状态"**未被覆盖**"，否则叶子无处安放。
- **第二个疑惑**：曾想加第四种状态"子级的子级"，因为"自己和子级都没装，要靠孙辈覆盖"。经引导想通：**"未覆盖"只向上传一层**——子节点返回 2（被覆盖）时，孙子那层的信息已在子节点内部消化成单个返回值，父节点无需再往下看。
- **认知转变一**：三状态本质就是两个维度（有摄像头 / 被覆盖）的穷举，没有第四种情况。
- **认知转变二**：先走了树形 DP 路线，逐步推导三个转移；`dp1` 一开始写错，被"两个叶子孩子"的反例纠正——**非放置侧的孩子不能是"未覆盖"**。
- **认知转变三**：空节点返回什么不是小事，而是整个递归的地基。通过"单节点树结果必须正确"反推出 `(INF, 0, 0)`，并踩到 INF 溢出成负数的坑。
- **认知转变四（压缩）**：发现 DP 返回三个值其实冗余——每个节点在给定孩子状态下，三个状态里**只有一个合法且最优**（其余非法或被支配），因此贪心每层只返回一个状态即可，且可通过归纳法严格证明与 DP 等价。
- **最后的确认**：把贪心分支穷举成 9 组合表格，确认无遗漏；并用 500 棵随机树 + 暴力枚举交叉验证两种解法全部通过。
