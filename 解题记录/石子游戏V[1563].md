# 石子游戏 V [1563]

## 1. 解题思路

**问题**：若干石子排成一行，Alice 每次将当前行**切成左右两个非空部分**。Bob 拿走价值较大的那一边（两边相等则任取一边），**被拿走的直接丢弃，不进入任何人的得分**；Alice 保留较小的一边继续分割。Alice 要最大化**自己累积得到的石子价值**。

**核心认知（先纠正两个直觉）**：

1. **这不是零和博弈**：Bob 拿走的石子被丢弃，不是"Bob 的得分"。所以目标不是"拉大净胜分差距"，而是**直接最大化 Alice 自己的累积得分**。DP 只优化 Alice。
2. **可以超过总数一半**：`[6,2,3,4,5,5]` 总和 25，答案却是 18（>12.5）。Alice 能在**多次相等分割**中每次拿当前区间的一半并继续榨取，累积超过一半。

**状态定义**（区间 DP）：

- `dp[l][r]` = Alice 在闭区间 `[l, r]` 上能获得的最大得分
- `dp[i][i] = 0`：单元素区间无法分割，不得分

**转移**：枚举切分点 `k`，左区间 `[l,k]` 和 `[k+1,r]`，用前缀和 O(1) 求两边和：

```
sumL = sum(l,k), sumR = sum(k+1,r)

sumL < sumR：Bob 拿走右边，Alice 保留左边继续 → sumL + dp[l][k]
sumL > sumR：Bob 拿走左边，Alice 保留右边继续 → sumR + dp[k+1][r]
sumL = sumR：两边任拿一边，再任选一个子区间继续 → sumL + max(dp[l][k], dp[k+1][r])
```

**填表顺序**（区间 DP 通用套路）：`dp[l][r]` 依赖**更短的内部子区间** `dp[l][k]`、`dp[k+1][r]`，长度不规则，无法用端点行列顺序覆盖。必须**按区间长度从小到大**填：每个长度内枚举所有起点。保证"子区间先于父区间"。

## 2. 代码实现

### V1：基础版 O(n³)

```java
package leetCode.difficult;

/**
 * @description: 1563. 石子游戏 V（动态规划）
 */
public class StoneGameV {
    public int stoneGameV(int[] stoneValue) {
        int n = stoneValue.length;
        // dp[i][r]：Alice 在闭区间 [i, r] 内能获得的最大得分
        int[][] dp = new int[n][n];
        int[] prefixSum = new int[n + 1];
        for (int i = 0; i < n; i++) {
            prefixSum[i + 1] = prefixSum[i] + stoneValue[i];
        }
        // 按区间长度从小到大填表，保证更短的子区间先被算好
        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int r = i + len - 1;                       // 区间右端点
                int sum = prefixSum[r + 1] - prefixSum[i]; // 区间 [i, r] 总和
                int max = Integer.MIN_VALUE;
                for (int k = i; k < r; k++) {
                    int left = prefixSum[k + 1] - prefixSum[i];
                    int right = sum - left;
                    if (left < right) {
                        max = Math.max(max, left + dp[i][k]);
                    } else if (left > right) {
                        max = Math.max(max, right + dp[k + 1][r]);
                    } else {
                        max = Math.max(max, left + Math.max(dp[i][k], dp[k + 1][r]));
                    }
                }
                dp[i][r] = max;
            }
        }
        return dp[0][n - 1];
    }
}
```

### V2：优化版 O(n²)

**优化原理**（详见第 4 节技巧总结）：

1. **单调分界点 k0**：`sum(i,k)` 随 k 单调不减、`sum(k+1,r)` 随 k 单调不增，所以"左小右大"与"左大右小"之间存在唯一分界 k0（满足 `2·sum(i,k0) < sum(i,r)` 的最后一个 k）。固定 i 时，r 越大 k0 只增不减 → 用单调指针，均摊 O(1)。
2. **前缀/后缀最大值表**：
   - `maxL[i][m] = max over k∈[i,m] (sum(i,k) + dp[i][k])`（只依赖左端点 i）
   - `maxR[m][r] = max over k∈[m,r-1] (sum(k+1,r) + dp[k+1][r])`（只依赖右端点 r）
3. 于是 `dp[i][r] = max(maxL[i][k0], maxR[k0+1][r], 相等切分点)`，查表 O(1)。

```java
    /**
     * 与 {@link #stoneGameV(int[])} 的区别（O(n³) → O(n²)）：
     * <p>原始版每个区间 [i,r] 都要遍历所有切分点 k 取 max，总 O(n³)。</p>
     * <p>本版利用两个关键性质省掉内层 k 扫描：</p>
     * 1. <b>单调分界点 k0</b>：sum(i,k) 随 k 单调不减、sum(k+1,r) 随 k 单调不增，
     *    所以"左小右大"与"左大右小"之间存在唯一分界 k0（满足 2·sum(i,k0) < sum(i,r) 的最后一个 k）。
     *    固定 i 时，r 越大 k0 只增不减 → 用单调指针维护，均摊 O(1)。
     * 2. <b>前缀/后缀最大值表</b>：
     *    maxL[i][m] = max over k∈[i,m] (sum(i,k) + dp[i][k])   （只依赖左端点 i，可增量构建）
     *    maxR[m][r] = max over k∈[m,r-1] (sum(k+1,r) + dp[k+1][r])（只依赖右端点 r，可增量构建）
     *    于是 dp[i][r] = max(maxL[i][k0], maxR[k0+1][r], 相等切分点) 查表 O(1)。
     * <p>辅助表每个格子 O(1) 增量算出，总复杂度 O(n²)。</p>
     */
    public int stoneGameV2(int[] stoneValue) {
        int n = stoneValue.length;
        if (n <= 1) {
            return 0;
        }
        int[][] dp = new int[n][n];
        int[] prefixSum = new int[n + 1];
        for (int i = 0; i < n; i++) {
            prefixSum[i + 1] = prefixSum[i] + stoneValue[i];
        }
        // maxL[i][m] = max over k∈[i,m] of (sum(i,k) + dp[i][k])，供"左小右大"分支
        int[][] maxL = new int[n][n];
        // maxR[m][r] = max over k∈[m,r-1] of (sum(k+1,r) + dp[k+1][r])，供"左大右小"分支
        int[][] maxR = new int[n][n];
        // 边界：单元素区间 [i,i] 无任何切分点
        // maxL[i][i] 对应唯一的切分点 k=i：sum(i,i)+dp[i][i] = stoneValue[i]+0
        // maxR[i][i] 对应 k∈[i,i-1] 空候选，应为 0
        for (int i = 0; i < n; i++) {
            maxL[i][i] = stoneValue[i];
            maxR[i][i] = 0;
        }
        // k0Ptr[i]：固定左端点 i 时当前的分界指针（单调不减），可为 i-1（表示左小右大分支为空）
        int[] k0Ptr = new int[n];
        for (int i = 0; i < n; i++) {
            k0Ptr[i] = i - 1;
        }
        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int r = i + len - 1;
                int total = prefixSum[r + 1] - prefixSum[i];
                // 先更新 maxR[i][r]（只依赖更短区间 dp[i+1][r]、maxR[i+1][r]，可提前算好供本区间查询）
                maxR[i][r] = Math.max(maxR[i + 1][r], (total - stoneValue[i]) + dp[i + 1][r]);
                // 单调推进分界指针 k0
                int k0 = k0Ptr[i];
                while (k0 + 1 <= r - 1 && 2 * (prefixSum[k0 + 2] - prefixSum[i]) < total) {
                    k0++;
                }
                k0Ptr[i] = k0;
                // 两部分候选：k ≤ k0 走左小右大（查 maxL），k > k0 走左大右小（查 maxR）
                int best = Integer.MIN_VALUE;
                if (k0 >= i) {
                    best = Math.max(best, maxL[i][k0]);
                }
                best = Math.max(best, maxR[k0 + 1][r]);
                // 相等切分点（最多一个）：k=k0+1 满足 2*sum(i,k) == total
                int kEq = k0 + 1;
                if (kEq <= r - 1 && 2 * (prefixSum[kEq + 1] - prefixSum[i]) == total) {
                    int half = prefixSum[kEq + 1] - prefixSum[i];
                    best = Math.max(best, half + Math.max(dp[i][kEq], dp[kEq + 1][r]));
                }
                dp[i][r] = best;
                // 再更新 maxL[i][r]（依赖 dp[i][r] 本身，故放在 dp 计算之后）
                maxL[i][r] = Math.max(maxL[i][r - 1], total + dp[i][r]);
            }
        }
        return dp[0][n - 1];
    }
```

## 3. 踩坑记录

- **不是零和博弈**：起初误以为 Bob 的丢弃部分算 Bob 得分，于是目标变成"拉大差距"。实际 Bob 拿走的直接丢弃，目标纯粹是最大化 Alice 得分。这决定了两分支直接用 `得分 + 继续区间`，而不是净胜分减法。
- **遍历顺序错乱（区间 DP 核心坑）**：第一版按"起点 i 外层 + 终点 j 内层"遍历，算 `dp[i][j]` 时 `dp[k+1][j]`（起点更大）还没算。必须**按长度分层**，保证更短的内部子区间先算好。
- **切分后子区间下标偏移**：切分点 k 切成左 `[i,k]`、右 `[k+1,r]`。容易把保留区间写成 `dp[i][k-1]` 或 `dp[k][r]`（偏移一位）。写完后要用具体区间手推一遍。
- **k 的上界**：`k ∈ [i, r-1]`（不能切出空区间），写成 `k <= r` 或 `k < r` 都容易越界或引入非法切分。
- **V2 的 maxR 更新时机**：`maxR[i][r]` 只依赖**更短区间**（`dp[i+1][r]`、`maxR[i+1][r]`），所以它**必须提前到 dp[i][r] 计算之前**更新；而 `maxL[i][r]` 依赖 `dp[i][r]` 本身，要放在之后。顺序反了答案就错。
- **V2 的 k0 可为 i-1**：若所有切分点都左大右小（左小右大分支为空），k0 应为 `i-1`，此时 `maxL` 分支不存在，只能查 `maxR[i][r]`。初始值必须设为 `i-1` 而非 `i`。

## 4. 技巧总结

- **"动作形态"决定状态结构**：1563 动作是"**分割区间**"（不是前缀取/两端取），剩余局面是任意子区间 `[l,r]` → 区间 DP，按长度填表。配合 486（两端取）、1140（前缀取）、1510（剩余石子数）对比记忆：**动作形态 → 状态维度**。
- **最大化自己 vs 净胜分**：本题 Bob 无决策权且丢弃不计分，是"单人最优化"，直接累加；真正的双人博弈才用"收益 − 对手优势"。判断标准：**对手拿走的是否计入某个得分**。
- **O(n³) → O(n²) 通用优化模式**（重点）：
  1. 找转移里随参数**单调**的分界（`2·sum(i,k) < total`）；
  2. 把 `max over k` 拆成"只依赖左端点"和"只依赖右端点"两部分；
  3. 各建**前缀/后缀最大值表** O(1) 增量维护；
  4. 分界点用单调指针（固定一端时随另一端只增不减）。
  - 关键点：被拆出的候选值**只依赖一端**（与另一端无关），才值得建表复用；若两个端点都依赖，建表没有意义。
- **区间 DP 通用模板**：`for len = 2..n { for i = 0..n-len { r = i+len-1; 枚举切分点 k; dp[i][r] = ... } }`，适用于 516、312 戳气球等。
- 相关经典解法：[博弈DP(零和博弈)](../经典解法/03-动态规划/博弈DP(零和博弈).md) 6.2.5 节。

## 5. 思考过程

本次学习基于与 agent 的对话完成：

1. **最初错误直觉**：以为"Bob 丢弃 = Bob 得分，剩余 = Alice 得分，二者总和固定，零和博弈，拉大差距即可"。被纠正：**Bob 无决策权且丢弃不计分**，这是单人最优化而非博弈。`[6,2,3,4,5,5]`→18（>总和一半）直接推翻"少于一半"的猜测。
2. **对半分直觉的对与错**：直觉"对半分留下最大"。部分对——不等分割时保留的小边尽量接近一半。但关键洞察是**相等分割是得分爆发点**（一次拿一半还能继续），所以最优是主动制造相等分割而非机械对半。
3. **无后效性确认**：`dp[l][r]` 只由区间内部子问题决定，与"它被哪个更大区间保留进来"无关——延续前几题的性质，但状态从一维变成二维区间。
4. **遍历顺序的纠结**：第一次按端点行列枚举发现子区间依赖长度不规则，无法用行列覆盖。想通后总结出区间 DP 的铁律：**按长度分层**。
5. **V2 优化的曲折**：理解"单调分界点 + 前缀/后缀 max 表"后，实现连续踩坑：`maxR` 更新顺序（必须先于 dp）、k0 可为 i-1、相等切分点单独处理。每个 bug 都靠与 v1 的随机对拍发现——**"优化版"必须保留朴素版做验证基准**，这是本次最重要的工程教训。
