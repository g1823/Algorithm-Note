# 数字 1 的个数 [233]

## 1. 解题思路

### 问题描述

给定整数 `n`，计算所有 ≤ n 的非负整数中数字 `1` 出现的总次数。

**示例**：`n = 13` → 输出 6（1, 10, 11, 12, 13 中共 6 个 1）

### 核心难点

直接遍历每个数逐位统计（O(n log n)）在大范围（n ≤ 10^9）下不可行，需要按**数位**批量统计。

### 解法：数位DP（逐位枚举 + 记忆化搜索）

将数字拆成逐个数位，DFS 遍历每一位所有可能的取值（0~9），同时用 `limit` 控制不超出上界，用缓存避免重复计算。

#### 算法思想

DFS 返回**二元组** `(count, sum)`：
- `count`：从当前位置到末尾能构造出多少个有效数字
- `sum`：这些数字中（从当前位置到末尾的部分）一共包含了多少个 1

每一层枚举当前位 `j`，递归获取子问题的结果 `next = [nextCount, nextSum]`：
- `count += nextCount`
- `sum += nextSum`
- 如果 `j == 1`：`sum += nextCount`（当前位的 1 在后续每个数字中各出现一次）

#### 关键参数

| 参数 | 含义 | 初始值 | 传递逻辑 |
|------|------|--------|----------|
| `cur` | 当前处理到的数位下标（高位到低位，0-indexed） | 0 | `cur + 1` |
| `limit` | 之前各位是否都与 n 的前缀一致 | `true`（空前缀一致） | `limit && (j == up)` |
| `leadZero` | 是否仍在处理前导零（即尚未遇到非零数字） | `true` | `leadZero && (j == 0)` |

#### 终止条件

当 `cur == numbers.length`（所有位处理完毕）：

| 情况 | 含义 | 返回 |
|------|------|------|
| `leadZero == true` | 从未选过非零数字 → 数字 0 | `[0, 0]` |
| `leadZero == false` | 构造了一个有效数字 | `[1, 0]` |

**为什么返回 `[1, 0]` 而不是统计 1？**
因为在递归过程中，每当某一位选择了数字 `1`，已经通过 `j == 1 → sum += nextCount` 的方式计入了。终止层只需要确认"这是一个有效数字"即可，无需重复计数。

#### 缓存设计

**缓存对象**：`limit = false` 且 `leadZero = false` 的子问题结果。

**为什么只缓存这两种状态？**

| 状态 | 原因 |
|------|------|
| `limit = true` | 受限路径只有一条（每一步都选上界值），数据量极小，无需缓存 |
| `limit = false, leadZero = true` | 要维持前导零，每层都只能选 0，只有唯一路径，无需缓存 |
| `limit = false, leadZero = false` | 之前选 1、2、3… 等不同值都能**汇聚到同一子问题**，缓存才有意义 |

**缓存结构**：`cache[cur] = [count, sum]`，初始化全 `-1`。

整个缓存设计的关键在于理解：**子问题的归约**——`(cur, limit=false, leadZero=false)` 是所有非受限、有效数字的起点，无论之前选了什么数字（只要不是前导零），后续的子问题结构完全相同。

#### 数字存储

将 n 的各数位**高位到低位**存入 `numbers` 数组（`numbers[0]` = 最高位），与 DFS 索引方向一致。

```
n = 345 → numbers = [3, 4, 5], len = 3
          cur=0  cur=1  cur=2
```

### 代码流程

```
getCount(n)
  ├── 算位数 len，构建 numbers[len]
  ├── 初始化 cache[len][2]（全 -1）
  └── dfs(0, true, true)[1]

dfs(cur, limit, leadZero)
  ├── cur == len → 终止，返回 [1, 0] 或 [0, 0]
  ├── !limit && !leadZero 且缓存命中 → 直接返回
  ├── 枚举 j = 0 ~ up
  │   └── 递归 next = dfs(cur+1, limit&&j==up, leadZero&&j==0)
  │       count += next[0]
  │       sum += next[1]
  │       if (j == 1) sum += next[0]  ← 核心贡献
  ├── !limit && !leadZero → 写缓存
  └── 返回 [count, sum]
```

## 2. 代码实现

```java
public class Solution {
    int[][] cache;
    int[] numbers;

    public int countDigitOne(int n) {
        // 提取各位数字（高位→低位）
        int temp = n, len = 0;
        while (temp > 0) { len++; temp /= 10; }
        numbers = new int[len];
        for (int i = 0; i < len; i++) {
            int pow10 = (int) Math.pow(10, len - 1 - i);
            numbers[i] = (n / pow10) % 10;
        }
        // 初始化缓存
        cache = new int[len][2];
        for (int i = 0; i < len; i++) {
            cache[i][0] = -1;
            cache[i][1] = -1;
        }
        return dfs(0, true, true)[1];
    }

    int[] dfs(int cur, boolean limit, boolean leadZero) {
        if (cur == numbers.length) {
            if (leadZero) return new int[]{0, 0};
            return new int[]{1, 0};
        }
        // 无限制 + 前导零已结束 → 查缓存
        if (!limit && !leadZero && cache[cur][0] != -1) {
            return new int[]{cache[cur][0], cache[cur][1]};
        }
        int up = limit ? numbers[cur] : 9;
        int count = 0, sum = 0;
        for (int j = 0; j <= up; j++) {
            int[] next = dfs(cur + 1,
                    limit && j == up,
                    leadZero && j == 0);
            count += next[0];
            sum += next[1];
            if (j == 1) {
                sum += next[0];  // 当前位的1在后续各数字中出现一次
            }
        }
        // 无限制 + 前导零已结束 → 写缓存
        if (!limit && !leadZero) {
            cache[cur][0] = count;
            cache[cur][1] = sum;
        }
        return new int[]{count, sum};
    }
}
```

## 3. 踩坑记录

### 1) `limit` 参数的传递逻辑

**错误写法**：`dfs(cur + 1, i < up, ...)`

`i < up` 的含义是"当前位选的值小于上界"，但这与 `limit` 的语义完全反了：
- `limit` 表示"后续是否受限"——只有当前受限 **且** 选了上界值，后续才继续受限
- 应写为 `limit && (i == up)`

**示例**（n=345，最高位 numbers[0]=3）：

| i | 含义 | 正确：`limit && i==up` | 错误：`i < up` |
|---|------|----------------------|----------------|
| 0 | 选了 0 < 3，后续自由 | `false` ✅ | `true` ❌ |
| 3 | 选了 3 = 3，继续受限 | `true` ✅ | `false` ❌ |

### 2) n = 0 的边界

当 `n = 0` 时，`len = 0`，`numbers = new int[0]`。`dfs(0, true, true)` 中 `cur == numbers.length`（0 == 0）立即触发终止条件，`leadZero = true` 返回 `[0, 0]`。结果正确。

### 3) 为什么终止条件不直接统计 1

数位DP有两种风格：
- **传参累加型**：向下传递 `countOne` 参数，终止时返回
- **返回聚合型**（本解法）：每层自己聚合子结果，终止只返回 `[1, 0]`

本解法采用后者，核心在于：递归返回时，每一层已经通过 `j == 1 → sum += nextCount` 统计了当前位的贡献，终止层不需要再处理了。

### 4) 缓存键为什么不需要 `cur` 位的具体值

缓存的位置是**选择当前位之前**。进入 `dfs(cur, false, false)` 时，当前位还没选，后续子问题只由 `cur` 决定（剩余位数相同），与之前选过什么具体值无关。所以 `cache[cur]` 就够了，不需要 `cache[cur][digitValue]`。

## 4. 技巧总结

- **数位DP三元组参数**：`(cur, limit, leadZero)` 是数位DP的"三件套"，熟练掌握可以解决绝大多数区间数位统计问题
- **双返回值模板**：`(count, sum)` 的返回形式比传参累加更简洁、更适合聚合型统计
- **缓存范围收窄**：只有 `!limit && !leadZero` 的状态才需要缓存，这能显著减少内存占用
- **贡献拆分**：当前位置选 1 时，它对答案的贡献 = `1 × 后续数字个数`，用 `sum += nextCount` 实现
- **终止层只计数不统计**：是理解数位DP"分治"思想的关键一环，每一层只关注自己这一位的贡献
