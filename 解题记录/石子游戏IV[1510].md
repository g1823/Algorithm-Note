# 石子游戏 IV [1510]

## 1. 解题思路

**问题**：一堆共 `n` 颗石子，两名玩家轮流取走**恰好一个完全平方数**（1、4、9、16…）颗石子，轮到某人时无法行动（石子不够取或已取完）即输。判断先手是否必胜。

**核心难点**：本题是"取到终态判胜负"型博弈（无法行动者输，而非比石子总数多者胜），因此取胜判定与前面几题不同——不需要"最大净胜分"，只需要布尔判定"能否让对手陷入必败态"。

**状态定义**（剩余石子数维度）：

- `dp[i]` = 剩余 `i` 颗石子时，当前玩家**能否必胜**（布尔）
- `dp[0] = false`：剩余 0 颗，无法行动，当前玩家必输

**转移方程**（必胜/必败态判定，normal-play）：

```
dp[i] = true  当且仅当  存在平方数 k² ≤ i，使得 dp[i-k²] == false
```

含义：当前玩家取走 `k²` 颗后，把"剩余 `i-k²` 颗、轮到对手"的局面留给他。**只要存在一种取法让对手处于必败态**，当前玩家就必胜（取到就赢，可提前 break）。

**为什么"存在一种"就够了（必胜/必败态的归纳自洽）**：

- `dp[j] == false` 的完整含义是：从 `j` 出发，**无论当前玩家（此时是对手）走哪一步**，都会到达一个必胜态，最终必输。
- 这个含义不是拍脑袋定义的，而是从终点 `dp[0] = false`（无路可走）一步步归纳上来的。
- 因此当当前玩家找到一步 `k²` 使 `dp[i-k²] == false` 时，对手接下来**无论怎么走**都会输——对手没有"可选的路"，不需要"保证对手按某条路走"。

**复杂度**：`n < 10^5`，状态数 `n`，每个状态枚举平方数到 `√i`（最多 316 个，因为 `316²=99856 ≤ 10^5 < 317²`），总 `≈ 3.16×10^7`，可行。

## 2. 代码实现

```java
package leetCode.difficult;

/**
 * @description: 1510. 石子游戏 IV
 * <p>有一堆石子，共 n 颗。两个玩家轮流取走【恰好】一个完全平方数（1, 4, 9, 16...）颗石子，
 * 无法行动者（石子不够取或已取完）输。判断先手是否必胜。</p>
 * <p>博弈DP（剩余石子数维度）：
 * 状态 dp[i] = 剩余 i 颗石子时，当前玩家是否必胜；
 * 必胜判定：存在一个平方数 k²≤i，使得 dp[i-k²] == false（把必败态留给对手）则 dp[i]=true。
 * 复杂度：O(n·√n)，n<10^5 时约 3.16×10^7 次，可行。</p>
 */
public class WinnerSquareGame {

    /**
     * 博弈DP：判断先手在 n 颗石子的游戏中是否必胜
     *
     * @param n 石子总数（n < 10^5，最多一次取 316² 颗）
     * @return true 表示先手必胜，false 表示先手必败
     */
    public boolean winnerSquareGame(int n) {
        // n < 10^5，最多一次取316²=99856颗，超过316²则超过n（317²>10^5）
        // dp[i]表示剩余i个石子时，当前决策者是否必胜
        boolean[] dp = new boolean[n + 1];
        // 没有石子的时候当前用户必输
        dp[0] = false;
        for (int i = 1; i <= n; i++) {
            // 枚举所有平方数取法：k² ≤ i（不能超过剩余石子数）
            for (int j = 1; j * j <= i; j++) {
                // 只要存在一种取法让对手面对必败态，当前玩家就必胜
                if (!dp[i - j * j]) {
                    dp[i] = true;
                    break;
                }
            }
        }
        return dp[n];
    }
}
```

## 3. 踩坑记录

- **误以为要二维数组**：曾想过 `dp[n][317]`（为每个平方数开一维）。想通后明白：`317` 个平方数是**动作集合**（每次转移要枚举的选择），不是**状态维度**。这里取 `k²` 颗不会像 1140 那样改变任何后续规则（没有 `M = max(M, X)`），所以状态只剩"剩余石子数"一维。
- **取法上限**：平方数 `k²` 必须 `≤ i`（剩余石子数），不能固定枚举到 316，否则会取超过剩余数量的石子（非法走法）。
- **必胜态误读**：一开始对"存在一种取法让对手必败 → 当前玩家必胜"感到困惑，误以为要"保证对手按某条路走"。实际上必败态的定义自带"无论对手怎么走都输"的承诺，见思路部分归纳自洽性。

## 4. 技巧总结

- **"取到终态判胜负" vs "比总和多者胜"**：前者用布尔必胜/必败态（存在性转移），后者用净胜分（最大最小转移）。先判断题目是哪种再选 dp 形态。
- **必胜态判定模板**：`dp[i] = ∃ 走法: dp[下一个局面] == false`，找到即 break。
- **状态维度由"动作是否改变规则"决定**：动作不改规则 → 只有局面维度；动作带动态参数（如 1140 的 M）→ 参数要加一维。结合 1406（博弈DP笔记 6.2.3 节的 `dp[i]`）和 [1140](石子游戏II[1140].md) 的 `dp[i][M]` 对比理解。
- **无后效性**依然成立：`dp[i]` 只依赖更少的剩余数 `i-k² < i`，与"之前怎么取到剩 i 颗"无关，所以从 0 正序填表即可。
- 相关经典解法：[博弈DP(零和博弈)](../经典解法/03-动态规划/博弈DP(零和博弈).md) 6.2.4 节。

## 5. 思考过程

本次学习基于与 agent 的对话完成：

1. **"强行博弈DP"可行**：最初直觉用 DP 但担心复杂度。算了下 `n < 10^5`，最多枚举 316 个平方数（`316²=99856`，`317²` 超界），总操作 `≈3.16×10^7`，直接暴力 DP 能过，无需找数学规律。
2. **状态维度的纠结点**：一度想开 `dp[n][317]`。被问"能否简化"后意识到——317 是动作集合，且取平方数不会改变任何后续规则（对比 1140 的 M 参数），所以 `dp[i]` 一维布尔数组足矣。
3. **必胜态概念的困惑与想通**：卡在"为什么只要一种取法让对手必败，当前玩家就必胜"和"怎么保证对手按这条路走"。想通的关键是：必胜/必败态是**归纳定义**的——`dp[j]==false` 本身就承诺"无论对手怎么走都输"（因为从 `dp[0]=false` 一路归纳上来），所以不存在"对手可选的路"，只要找到一个 `dp[i-k²]==false` 就可以立刻判定必胜并 break。
4. **认知转变**：从"把必胜当直觉"到"理解必胜态是存在性 + 必败态是全称承诺的归纳结构"。这比会套模板更接近博弈 DP 的本质。
