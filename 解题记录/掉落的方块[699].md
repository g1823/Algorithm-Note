# 699. 掉落的方块

## 1. 解题思路

### 问题转换

每个方块用 `[left, sideLength]` 表示，落下时占据 x 区间 `[left, left + sideLength)`，即半开区间 `[L, R)`（`R = L + side`）。

方块是"竖直落下"的：它落在该区间**当前已有最大高度**之上，因此：
- 落点高度 `h = 查询区间 [L, R) 的当前最大高度`
- 方块自身高度是 `side`，落地后该区间整段的高度变为 `h + side`
- 返回每次落地后**全局最大高度**

核心操作 = **区间查最大值** + **区间赋值（set）** + **动态维护全局最值**。

### 与 732（我的日程安排表 III）的对比

两题底子都是"线段树 + 区间最值"，但有三个关键不同：

| 维度 | 732 | 699 |
|------|-----|-----|
| 更新语义 | 区间 **+1**（ADD，可累加） | 区间 **赋值**（SET，必须覆盖） |
| 查询目标 | 每次更新后直接返回**全局**最大值 | 先查**目标区间**最大值确定落点，再设区间 |
| 操作数 | 只有 updateAdd | 必须同时支持 queryMax 与 updateSet（先查再设） |

最关键的一点：**699 是 SET 不是 ADD**。方块之间在 y 轴可能有空隙，落下去后整段被"压平"成同一个新高度，绝不能把新高度加到旧高度上。

### 离散化（坐标压缩）

x 坐标可达 10⁸，但 `positions` 一次性给定，所以**所有端点都预先可知**，可以直接离散化：

1. 收集每个方块的 `L` 与 `R = L + side`，丢进 `Set` 排序去重，得到有序数组 `X`
2. 离散化后每个叶子 `i` 代表一段连续区间 `[X[i], X[i+1])`（注意是**段**不是点）
3. 原半开区间 `[L, R)` 映射到叶子下标 `[lo, hi]`：
   - `lo = X 中 L 的下标`
   - `hi = X 中 R 的下标 - 1`（**开区间必须 -1**，否则相邻方块在边界误判重叠）

因为所有 `L`、`R` 都来自 `X`，必然精确命中，不存在"夹在中间"的情况，下标转换是干净的 O(1)。

### 数组式线段树（堆式编号）

因为叶子区间是连续整数 `[0, N-1]`，完全不需要 Node 对象。用堆式数组：
- 根节点下标 `1`
- 节点 `i` 左孩子 `2*i`、右孩子 `2*i+1`
- 平行数组 `tree[]`（区间最大高度）、`lazy[]`（SET 懒标记，`-1` 表示无）

## 2. 代码实现

> 代码库：`Algorithm-Cote/src/leetCode/difficult/FallingSquares.java`

```java
package leetCode.difficult;

import java.util.*;

/**
 * @description: 699. 掉落的方块
 * @author: gj
 */
public class FallingSquares {

    public List<Integer> fallingSquares(int[][] positions) {
        // 1、统计所有端点：因为预先知道全部方块数据，可直接得到每个 x 区间（端点），从而精确离散化
        Set<Integer> set = new HashSet<>();
        for (int[] position : positions) {
            set.add(position[0]);                 // 左端点 L
            set.add(position[0] + position[1]); // 右开端点 R = L + side
        }
        // 对端点排序，得到有序的 x 端点数组 X
        int[] arr = set.stream().mapToInt(Integer::intValue).toArray();
        Arrays.sort(arr);
        // 端点值 → 下标 的映射（直接 O(1) 拿到离散化下标）
        Map<Integer, Integer> map = new HashMap<>();
        for (int i = 0; i < arr.length; i++) {
            map.put(arr[i], i);
        }
        // 初始化线段树（n 取坐标个数；实际只用前 n-1 个叶子段，多开一个无害）
        SegmentTree seg = new SegmentTree(arr.length);
        List<Integer> res = new ArrayList<>();
        for (int[] position : positions) {
            int x = position[0];
            int y = position[1];                      // 边长 = 方块高度
            int l = map.get(x);                       // 左端点离散下标
            int r = map.get(x + y) - 1;             // 右开端点离散下标，开区间必须 -1
            seg.update(l, r, y);                     // 传入边长 y 作为增量
            res.add(seg.getMax());                   // 每次落地后的全局最大高度
        }
        return res;
    }

    /**
     * 数组式线段树：区间最大值查询 + 区间赋值（SET）懒标记
     */
    static class SegmentTree {
        int[] tree;   // tree[i]：节点 i 所管区间的当前最大高度
        int[] lazy;   // lazy[i]：节点 i 的 SET 懒标记；-1 表示无待下发标记
        int n;        // 叶子段数（此处取坐标个数）
        int max;      // 全局最大高度（每次 update 时维护）

        public SegmentTree(int n) {
            this.n = n;
            this.tree = new int[n * 4];      // 数组线段树开 4 倍空间足够
            this.lazy = new int[n * 4];
            Arrays.fill(lazy, -1);           // -1 表示无懒标记
            this.max = 0;
        }

        /** 返回当前全局最大高度 */
        public int getMax() {
            return max;
        }

        // ============ 查询：区间最大值 ============
        public int query(int l, int r) {
            if (l > r || r < 0 || l > n - 1) return 0;
            return query(1, 0, n - 1, l, r);   // 根节点下标为 1
        }

        private int query(int node, int start, int end, int l, int r) {
            if (start > r || end < l) return 0;                 // 与查询区间无交
            if (start >= l && end <= r) return tree[node];      // 被查询区间完全包住，直接返回
            pushDown(node);                                    // 下推懒标记，保证孩子值最新
            int mid = (start + end) / 2;
            // 部分覆盖：取左右孩子在该区间内的较大值（只读，不写回）
            return Math.max(query(node * 2, start, mid, l, r),
                            query(node * 2 + 1, mid + 1, end, l, r));
        }

        // ============ 更新：区间赋值为 newMax = 当前 max + 边长 ============
        public void update(int l, int r, int val) {
            if (l > r || r < 0 || l > n - 1) return;
            int curMax = query(l, r);          // 先查：目标区间当前最大高度（落点）
            int newMax = curMax + val;        // 新高度 = 落点高度 + 边长
            max = Math.max(max, newMax);     // 维护全局最大值
            update(1, 0, n - 1, l, r, newMax);
        }

        private void update(int node, int start, int end, int l, int r, int newMax) {
            if (start > r || end < l) return;                     // 无交
            if (start >= l && end <= r) {                        // 被更新区间完全包住
                tree[node] = newMax;                            // SET：整段直接覆盖
                lazy[node] = newMax;                           // 挂上 SET 懒标记
                return;
            }
            pushDown(node);                                    // 局部覆盖：先下推，保住未覆盖孩子的旧值
            int mid = (start + end) / 2;
            update(node * 2, start, mid, l, r, newMax);
            update(node * 2 + 1, mid + 1, end, l, r, newMax);
            tree[node] = Math.max(tree[node * 2], tree[node * 2 + 1]);  // 再上传：父节点 = 两孩子较大值
        }

        // ============ 懒标记下推（SET 语义：覆盖而非累加） ============
        private void pushDown(int node) {
            if (lazy[node] != -1) {
                int v = lazy[node];
                // 孩子直接被覆盖成 v（SET 与 ADD 的 lazy 最大区别：ADD 是 +=，SET 是直接 =）
                tree[node * 2] = v;     lazy[node * 2] = v;
                tree[node * 2 + 1] = v; lazy[node * 2 + 1] = v;
                lazy[node] = -1;          // 清除自身标记
            }
        }
    }
}
```

## 3. 踩坑记录

本题在实现中暴露了 4 个层层递进的错误，全部通过具体反例定位：

### 坑 1：离散化右端点漏写 `-1`

```java
int r = map.get(x + y) - 1;   // 必须 -1
```

`[L, R)` 是半开区间。若漏掉 `-1`，方块 A `[1,3)` 与方块 B `[3,5)` 会在坐标 3 处误判重叠、错误叠高。反例 `[[1,2],[2,3],[6,1]]` 本应得 `[2,5,5]`。

### 坑 2：query 里错误"写回" `tree[node]`

最早版本在 query 的部分覆盖分支末尾写了：
```java
tree[node] = curMax;   // ❌ 错
lazy[node] = -1;       // ❌ 错
```
query 是**只读**操作。`curMax` 只是 `[start,end] ∩ [l,r]` 这段**子区间**的最大值，不是节点整段的最大值；把它写回 `tree[node]` 会污染该节点原本正确的整段最大值，导致后续整段命中它时读到错误值。删除这两行即可——`pushDown` 已经把挂起的更新落实到孩子，`tree[node]` 本就正确。

### 坑 3：update 局部分支漏写 `pushUp`

局部覆盖分支最初只写了 `pushDown` 和递归，最后 `lazy[node] = -1;`（多余且无上传）：
```java
pushDown(node);
update(left, ...);
update(right, ...);
// 漏了：tree[node] = Math.max(tree[left], tree[right]);
```

局部更新只改了部分孩子，父节点跨"改了 / 没改"两半，必须 `tree[node] = max(左, 右)` 重算。否则内部节点 `tree` 失真，一旦某次查询**整段命中**该内部节点，就返回偏小的旧值。

反例 `[[1,4],[1,1],[1,5]]`：第三块应落在新高度 5 上得 `[4,5,10]`，漏 pushUp 时得到 `[4,5,9]`（第三块落点高度被低估 1）。

### 坑 4：落点高度被双重累加

`fallingSquares` 先 `query` 出 `height`，又传 `height + y` 给 `update`；而 `update` 内部又 `curMax = query(...); newMax = curMax + val`，于是：

```
newMax = height + (height + y) = 2*height + y   // 高度被翻倍
```

最终采用**方案 B**：`fallingSquares` 只传边长增量 `y`，由 `update` 内部统一算 `curMax + val`，语义清晰、无重复。反例 `[[1,2],[2,3]]` 漏此 bug 时得 `[2,7]`，正确应为 `[2,5]`。

## 4. 技巧总结

| 技巧 | 关联文件 | 说明 |
|------|----------|------|
| 离散化（坐标压缩） | - | 坐标值域大但全集已知时，收集端点排序去重再映射（暂无独立文件，详见本题「1. 解题思路 · 离散化」） |
| 半开区间映射 `-1` | 本题 | 连续区间离散化后叶子代表段 `[X[i],X[i+1])`，右端点下标需 `-1` |
| 线段树 · SET 懒标记 | `经典解法/01-数据结构/线段树.md` | 区间赋值用 SET（覆盖），与 ADD（累加）的 lazy 合并策略不同 |
| 数组式线段树 | `经典解法/01-数据结构/线段树.md` | 堆式编号 root=1, left=2i, right=2i+1，平行数组代替 Node |
| 先查再设（query→update） | 本题 | 落点高度依赖查询结果，必须查询完再执行区间更新 |

> SET 懒标记 vs ADD 懒标记：ADD 下推时 `child += v` 可叠加；SET 下推时 `child = v` 直接覆盖，新标记会顶掉旧标记。这是 699 与 732 在 lazy 实现上的根本分野。

## 5. 思考过程

### 初始类比：699 ≈ 732

刚拿到题时，第一反应是它和 `732. 我的日程安排表 III` 几乎一样——都是"区间最值 + 懒标记线段树"。当时认为唯一区别是：732 求的是**全局**最值，699 求的是**部分区间**的最值。

这个直觉方向对，但太浅。经过引导，逐步挖出两个被忽略的本质差异：

1. **732 是区间 ADD（+1），699 是区间 SET（赋值）**。加法和赋值的懒标记合并策略完全不同。
2. **699 必须先 query 目标区间最大值（决定落点），再 update 区间设成新值**，是"先查再设"的两步操作；732 只做一次 updateAdd 即可。

### 关于"能不能离散化"的反复

一开始觉得坐标到 10⁸，似乎没法离散化。随后意识到 `positions` 是**一次性给定**的，所有方块的 `L` 和 `R` 都能提前收集，于是离散化完全可行，且比动态开点更省内存。

接着卡在"映射到底怎么算"。核心认知转折是：**离散化后每个叶子代表一段连续区间 `[X[i], X[i+1])`，不是点**。由此推导出 `lo = idx(L)`、`hi = idx(R) - 1`——`-1` 来自半开区间 `[L, R)`，右边界不含。若不用 `-1`，相邻方块会在边界坐标上误判重叠。

### 从 Node 对象到数组线段树

之前写线段树习惯用 Node 类（left/right 指针 + 字段）。这题因为叶子下标是连续整数，切换到**堆式数组**：root=1，孩子 2i / 2i+1，用 `tree[]`、`lazy[]` 两个平行数组代替对象字段。逻辑完全一致，只是指针换成了下标计算。

### 四个错误点的逐层暴露

整个实现是"改一个、冒一个"地推进，每个错误都配了具体反例：

1. **`r` 漏 `-1`** → 相邻方块边界重叠误判。
2. **query 里写回 `tree[node]`** → 误以为"pushDown 已经更新了，需要把当前节点值也刷一下"，实则 query 应只读，写回会用局部 `curMax` 污染整段最大值。
3. **update 局部分支漏 `pushUp`** → 直觉是"最大值是覆盖，直接用 `newMax` 就好，不用重算"，忘记了局部分支父节点横跨"改了+没改"两半，必须用 `max(左, 右)` 重算。
4. **落点高度双重累加** → `fallingSquares` 传 `height + y`、`update` 又 `curMax + val`，`height` 被加两次。最终统一为方案 B：外部只传边长增量 `y`，由 `update` 内部算 `curMax + val`。

### 验证方式

用 JDK 1.8 手动编译（`javac -encoding UTF-8`，注意中文注释需指定编码）并跑了 5 个样例，全部与预期一致：

```
[2, 5, 5]       // [[1,2],[2,3],[6,1]]
[4, 5, 10]      // [[1,4],[1,1],[1,5]]
[4, 5, 5, 6]    // [[1,4],[1,1],[2,1],[2,1]]
[1, 3]           // [[2,1],[2,2]]
[2, 5]           // [[1,2],[2,3]]
```

至此整条链路（离散化 → 数组线段树 → query 只读 → update 整段 SET + 局部 pushUp → 增量语义）完全打通。
