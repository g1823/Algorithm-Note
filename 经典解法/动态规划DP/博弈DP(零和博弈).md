# 博弈DP（零和博弈）

## 1. 什么是博弈DP

博弈DP（博弈论动态规划，也称 minimax / 最大最小 DP）是动态规划在**双人零和博弈**中的应用。

**零和博弈**：两名玩家轮流行动，一方所得即另一方所失（总收益为 0）。因此"当前玩家"和"对手"的收益互为相反数——对手的优势就是我的劣势。

**核心思想**：由于双方都采取最优策略，当前玩家的每一步都要"站在对手的角度"预判后续结果。当前选择的收益 = **本轮拿到的收益 − 对手在剩余局面下能获得的最大优势**。这样就把"我如何最优"和"对手如何最优"统一在一个递推式中。

> 这就是 minimax 思想：我的行动选择 max（对己最优），对手的行动选择 min（对我最差），合并为 `dp = max(拿到的 − 对手后续优势)`。

**注意**：博弈DP 的"动作形态"远不止两端取数一种。只要满足双人轮流 + 零和，动作可以是"取前若干堆""取完全平方数颗""分割区间""任选一个元素"……动作形态决定状态设计（区间/下标/掩码/参数），但"净胜分 + 对手视角"的思想不变。石子游戏全系列（877/1140/1406/1510/1563/1686/1690）正是这种多样性的最佳展示，见 6.2 节。

## 2. 通俗理解：分糖果场景

> 如果你第一次接触博弈DP，先不要看公式。先把这个场景吃透，回头再看公式，每个符号都会有画面感。

想象你和同桌轮流从一排糖果的两头拿，谁拿的总数多谁赢。你的目标只有一个：**不让他比你多**。

### 2.1 dp 存的不是"你能拿多少"，而是"我比你多多少"

`dp` 表格里存的值，**不是"某人能拿到多少糖"，而是"轮到某人时，他最后能比对方多拿多少糖"**。

"多多少"比"拿多少"聪明在哪？两个人一起涨的分被抵消掉了。就像说"我比你高 5 厘米"，不用管我们各自多高，这个数就已经回答了"谁赢、赢多少"。

### 2.2 为什么是减法：你拿了之后，剩下就归对手折腾

现在轮到你了。假设你伸手拿左边那颗，价值 `nums[l]`。

你拿了之后，**剩下的糖果全归对手处理**。对手不是傻子，他会在这段里拼命多拿。他最后能比你多拿多少？答案就写在表里：`dp[l+1][r]`（因为"剩下的那段区间 + 轮到对手"和"当前决策者 + 区间"是同一个问题）。

所以账这么算：

```
我真正的净赚 = 我这一手拿的 - 对手接下来能从我这儿赚回去的
            = nums[l]        - dp[l+1][r]
```

**你在给对手"送货上门"——每拿一颗，就等于借给对手一个局面，他会在那个局面里把便宜占尽。** 减掉的那部分，就是要付给对手的"回扣"。

### 2.3 为什么取 max：你当然要挑对自己最有利的一端

你有两个选择：拿左边、拿右边。每种都能算出"最终我比他多多少"：

```
拿左边：nums[l] - dp[l+1][r]
拿右边：nums[r] - dp[l][r-1]
```

取大的那个。`max` 不是数学技巧，是"人要挑对自己好的"。

### 2.4 手算演示：nums = [3, 9, 1, 2]

从短区间填到长区间，就像拼图从小块拼到大块。

**第 1 步：只有 1 颗糖的区间**（没得选）：

```
dp[0][0] = 3    dp[1][1] = 9    dp[2][2] = 1    dp[3][3] = 2
```

**第 2 步：2 颗糖的区间**

区间 [9,1]：拿 9 对手拿 1，我多 8；拿 1 对手拿 9，我少 8。选拿 9，`dp[1][2] = 8`。

区间 [3,9]：同理 `dp[0][1] = max(3-9, 9-3) = 6`。区间 [1,2]：`dp[2][3] = max(1-2, 2-1) = 1`。

**第 3 步：3 颗糖的区间 [3,9,1]**

- 拿 3 → 剩 [9,1] 给对手，对手比我多拿 `dp[1][2] = 8`，我净赚 `3 - 8 = -5`（亏 5 颗）
- 拿 1 → 剩 [3,9] 给对手，对手比我多拿 `dp[0][1] = 6`，我净赚 `1 - 6 = -5`
- 两条路都亏 5：`dp[0][2] = -5`

**注意这个负数！** 它说明：**轮到谁面对 [3,9,1]，谁就注定亏 5 颗**。这正是"当前决策者"视角的体现——表格不关心你是先手还是后手，谁轮到他就是"当前决策者"。

同理 `dp[1][3]`：拿 9 → `9 - dp[2][3] = 8`；拿 2 → `2 - dp[1][2] = -6`。取 `dp[1][3] = 8`。

**第 4 步：整个数组 [3,9,1,2]**

- 拿左边 3 → 剩 [9,1,2] 给对手，对手比我多拿 `dp[1][3] = 8`，我净赚 `3 - 8 = -5`
- 拿右边 2 → 剩 [3,9,1] 给对手，对手面对它是 `dp[0][2] = -5`（即对手亏 5，等于我赚 5），我净赚 `2 - (-5) = 7`

所以 `dp[0][3] = max(-5, 7) = 7`，**大于 0，先手赢，赢 7 颗**。

与直接模拟一致：先手拿 2（拿小的），后手只能从 [3,9,1] 里拿 3 或 1，先手都能抢到 9。最终先手 11 对后手 4，正好多 7。

## 3. 适用场景

满足以下特征的问题，大概率可以用博弈DP：

| 特征 | 说明 |
|------|------|
| **双人轮流行动** | 两名玩家交替决策，直到游戏结束 |
| **零和** | 一方得分即另一方失分，净胜分总和为 0 |
| **双方都最优** | 玩家都会选择对自己最有利、对对手最不利的策略 |
| **有明确终态** | 游戏结束时能确定谁赢或双方净胜分 |
| **局面可枚举** | 状态空间有限，可用 DP 递推或记忆化搜索 |

常见题型：轮流从数组两端取数、轮流拿石子（Nim 变体）、轮流取前若干堆（1140/1406）、取完全平方数（1510）、分割区间（1563）、带权任取（1686）、轮流选数字凑目标、棋盘类游戏判定先手必胜。

## 4. 核心模板

### 4.1 通用范式（minimax）

```
dp[局面] = max(
    本轮拿到的收益 - dp[我拿完后的局面]，  // 该局面对手能领先我多少
    其他可选行动的对应值
)
```

关键点：`dp` 存的不是"当前玩家的得分"，而是**当前玩家相对对手的净胜分**。由于零和，对手的净胜分取负就是我的净胜分，所以转移里是**减法**而非加法。

### 4.2 区间博弈模板（数组两端取数，486 / 877）

```java
// dp[l][r]：在区间 [l, r] 内，当前玩家相对对手最多能领先多少分
int[][] dp = new int[n][n];
for (int i = 0; i < n; i++) dp[i][i] = nums[i];   // 只有一个数，直接拿走
for (int len = 1; len < n; len++) {                // 按区间长度从小到大
    for (int l = 0; l + len < n; l++) {
        int r = l + len;
        dp[l][r] = Math.max(
            nums[l] - dp[l + 1][r],   // 拿左边：本轮拿 nums[l]，对手在 [l+1, r] 领先 dp[l+1][r]
            nums[r] - dp[l][r - 1]    // 拿右边：本轮拿 nums[r]，对手在 [l, r-1] 领先 dp[l][r-1]
        );
    }
}
return dp[0][n - 1] >= 0;   // 先手净胜分 >= 0，即先手至少不败
```

### 4.3 记忆化搜索形式（局面较复杂时）

```java
// memo[s]：局面 s 下当前玩家的净胜分
int dfs(int s) {   // s 为局面状态（可用位掩码/参数组表示）
    if (终态) return 0;                          // 或返回确定的胜负值
    if (memo[s] != null) return memo[s];
    int best = Integer.MIN_VALUE;
    for (每种可选行动 a) {
        best = Math.max(best, 本轮收益(a) - dfs(下一个局面));
    }
    return memo[s] = best;
}
```

## 5. dp 表的含义与"当前决策者"视角

### 5.1 dp[i][j] = k 的精确含义

> **dp[i][j] = k 表示：在区间 [i, j] 内，当前决策者（轮到行动的人）最终能比对方高出 k 分。无论当前决策者是谁，结果都是这个 k。**

两个关键推论：

1. **值与"轮到谁"无关，只与区间有关**——谁轮到他，他就是"当前决策者"，公式一模一样。
2. **先手赢不赢，直接看 dp[0][n-1]**——整局第一步的当前决策者就是先手，所以 `dp[0][n-1]` 的视角天然是先手，**不需要变号**，`k >= 0` 就是先手至少不败。

### 5.2 为什么用"当前决策者"视角，而不是"先手"视角

想象你固定以"先手"为基准定义 dp：

- 轮到先手时：dp 直接是"先手 - 后手"
- 轮到后手时：dp 变成"后手 - 先手" = 负的先手净胜

这时递推式必须**区分轮到谁**，状态里要多塞一维"这一步轮到谁"，否则一个公式写不出来。

而"当前决策者"视角**把这一维删掉了**——它把"以谁为基准"这个信息藏进了 dp 值的符号里：轮到后手时，后手作为当前决策者算出 k，表示"后手相对先手高 k"，即先手相对后手是 -k。**负号就是这个视角切换的唯一痕迹。**

### 5.3 减号的三重作用

转移方程 `nums[l] - dp[l+1][r]` 里的减号，同时干了三件事：

1. **兑现零和博弈**：对方所得 = 我方所失
2. **完成视角切换**：下一格轮到对手，取其负值，就换回"当前决策者"视角
3. **抵消总分信息**：净胜分把"两人得分"压缩成"一人一变量"，无需维护剩余总和

### 5.4 k 与两人得分的换算

如果 `dp[0][n-1] = k`，整副牌总和为 T，则：

```
先手得分 = (T + k) / 2
后手得分 = (T - k) / 2
```

例：[3,9,1,2] 总和 15，k = 7，先手 (15+7)/2 = 11，后手 (15-7)/2 = 4。

### 5.5 状态设计原则

| 设计点 | 说明 |
|--------|------|
| **谁是"当前玩家"** | dp 表达式中不区分先手/后手，只区分"当前行动者"，任何一步都站在当前行动者视角计算 |
| **dp 存净胜分而非得分** | 这样才符合零和性质，转移用 `收益 − 对手优势` 而非 `收益 + 对手得分` |
| **终态明确** | 无剩余可拿时净胜分为 0；单元素区间直接取走该数 |
| **依赖更小子问题** | 区间型按长度从小到大填表；其余用记忆化搜索避免重复 |

**6.2.2 1140. 石子游戏 II（取前 X 堆 + 可变参数 M）**

每次可从前端取 1~2M 堆，取完后 `M = max(M, X)`，初始 M=1，总分多者胜，求先手最大得分。

```java
// dp[i][M]：从第 i 堆开始、当前参数为 M 时，当前玩家能拿到的最大石子数
// 后缀和 suffix[i] = piles[i] 到 piles[n-1] 的总和
int[][] dp = new int[n + 1][n + 1];
for (int i = n - 1; i >= 0; i--) {
    for (int M = 1; M <= n; M++) {
        int best = 0;
        for (int X = 1; X <= 2 * M && i + X <= n; X++) {
            // 本轮拿 X 堆后，对手在剩余区间拿 dp[i+X][max(M,X)]
            best = Math.max(best, suffix[i] - dp[i + X][Math.max(M, X)]);
        }
        dp[i][M] = best;
    }
}
return dp[0][1];
```

要点：博弈 DP 可以携带**额外的动态参数 M**，状态维度增加但转移思想不变。

详细解答见：[解题记录/石子游戏II[1140].md](../../解题记录/石子游戏II[1140].md)

**6.2.3 1406. 石子游戏 III（前缀取 1/2/3 堆，值可为负，可能平局）**

每次从前端取 1/2/3 堆，石子值可为负数，总分多者胜（可能平局），返回 `"Alice"/"Bob"/"Tie"`。

```java
// dp[i]：从 i 开始，当前玩家相对对手的净胜分（可为负）
// suffix[i] = 从 i 到末尾的总和
int[] dp = new int[n + 1];          // dp[n] = 0
for (int i = n - 1; i >= 0; i--) {
    dp[i] = Integer.MIN_VALUE;
    for (int k = 1; k <= 3 && i + k <= n; k++) {
        dp[i] = Math.max(dp[i], suffix[i] - dp[i + k]);
    }
}
// dp[0] > 0 → Alice；dp[0] < 0 → Bob；dp[0] == 0 → Tie
```

要点：有负数 → 不能贪心（必须 DP）；存在平局 → 结果是一个三分支判断而非布尔。

**实现补充（动作固定，可不写后缀和）**：既然只取 1/2/3 堆，动作固定，直接用**累加 sum** 枚举即可，连后缀和都省了：

```java
int[] dp = new int[n + 1];          // dp[n] = 0
for (int i = n - 1; i >= 0; i--) {
    int max = Integer.MIN_VALUE, sum = 0;
    for (int j = i; j < i + 3 && j < n; j++) {
        sum += stoneValue[j];                       // 先累加本轮收益
        max = Math.max(max, sum - dp[j + 1]);       // 再算净胜分
    }
    dp[i] = max;
}
```

**踩坑点（重要）**：累加循环里必须先 `sum += stoneValue[j]` 再计算。若直接写 `stoneValue[j] - dp[j+1]`，则只算了"取到第 j 颗这一颗"的收益，**漏掉了前面 i..j-1 的累加**，导致只有取 1 个正确、取 2/3 个全部算错——代码看似合理实则答案是错的。

**思维进阶（最优子结构 + 无后效性）**：为什么一维 `dp[i]` 就够、从后往前填就行？因为状态满足：

- **最优子结构**：`dp[i]` 的最优解由 `dp[i+1]/dp[i+2]/dp[i+3]` 的最优解拼接而成，子问题可独立复用。
- **无后效性（马尔可夫性质）**：`dp[i]` 的值只取决于"从 i 开始的后缀"，**与前 i 堆如何被取光的历史完全无关**。无论之前经历多少步、谁拿走了什么，只要当前局面是"从 i 开始、轮到当前玩家"，`dp[i]` 就是同一个值。

这两条性质是所有博弈 DP（含二维的 1140）都能安全"从后往前填表"的根本保证：填表时只看更大的下标，不需要回看历史。

**6.2.4 1510. 石子游戏 IV（取完全平方数颗，无法行动者输）**

一堆 n 颗石子，每次取任意非零完全平方数颗（1、4、9…），轮到某人无法行动即输。

```java
// dp[i]：剩余 i 颗石子时，当前玩家能否必胜
boolean[] dp = new boolean[n + 1];
for (int i = 1; i <= n; i++) {
    for (int k = 1; k * k <= i; k++) {
        if (!dp[i - k * k]) {   // 存在一步让对手必败 → 我方必胜
            dp[i] = true;
            break;
        }
    }
}
return dp[n];
```

要点：这是"取到终态判胜负"型博弈（谁先走不了谁输），转移为**找一步使对手处于必败态**，即"存在性"而非"最大最小"。

> 详细解答见：[解题记录/石子游戏IV[1510].md](../../解题记录/石子游戏IV[1510].md)

**6.2.5 1563. 石子游戏 V（分割行，Bob 只抛不累分）**

Alice 把当前行分成左右两非空行，Bob 抛掉价值较大的行，Alice 得分加上剩余行的价值；两行相等时 Alice 决定抛哪行。剩余行继续玩，直到只剩一颗。

```java
// dp[i][j]：区间 [i,j] 内 Alice 能获得的最大得分（前缀和求区间和）
int[][] dp = new int[n][n];
for (int len = 2; len <= n; len++) {
    for (int i = 0; i + len - 1 < n; i++) {
        int j = i + len - 1, best = 0;
        for (int k = i; k < j; k++) {
            int left = sum(i, k), right = sum(k + 1, j);
            if (left < right)      best = Math.max(best, left + dp[i][k]);      // 抛右边，继续玩左边
            else if (left > right) best = Math.max(best, right + dp[k + 1][j]); // 抛左边，继续玩右边
            else                   best = Math.max(best, left + Math.max(dp[i][k], dp[k + 1][j]));
        }
        dp[i][j] = best;
    }
}
return dp[0][n - 1];
```

**注意**：本题不是传统零和博弈——Bob 拿走的石子**直接丢弃不计入任何得分**，且 Bob 无决策权，本质是 Alice 的**单人最优化**，故直接累加得分而非净胜分。可用 O(n²) 优化（单调分界点 k0 + 前缀/后缀最大值表），见下方详细笔记。

> 详细解答见：[解题记录/石子游戏V[1563].md](../../解题记录/石子游戏V[1563].md)

要点：本游戏**只累计 Alice 的得分，Bob 是纯"抛掷者"不累分**——零和但不对称，不能套 `max(拿到的 − 对手优势)`，只做 Alice 单方分数最大化的区间 DP。

**6.2.6 1686. 石子游戏 VI（双视角价值，排序贪心）**

每个石子对 Alice 的价值为 `aliceValues[i]`、对 Bob 的价值为 `bobValues[i]`。轮流任取一个，取者获得自己的价值，总分高者胜。

```java
// 关键洞察：某个石子对双方的价值之和越大，越值得先抢（双方都想要它）
// 按 aliceValues[i] + bobValues[i] 降序排列，Alice 取偶数位，Bob 取奇数位
Integer[] idx = ...; // 按下标对 alice+bob 降序排序
for (int i = 0; i < n; i++) {
    if (i % 2 == 0) alice += aliceValues[idx[i]];
    else            bob   += bobValues[idx[i]];
}
return Integer.compare(alice, bob);   // 1 Alice 胜，-1 Bob 胜，0 平局
```

要点：**博弈不一定用 DP**——当动作可任意选择（不受位置约束）、且总收益线性可加时，可能退化为**排序/贪心**。排序键是 `a+b`（战略价值 = 自己所得 + 对手失去），而非"差"，用交换论证证明。

> 详细解答见：[解题记录/石子游戏VI[1686].md](../../解题记录/石子游戏VI[1686].md)

**6.2.7 1690. 石子游戏 VII（两端取，得分 = 剩余总和）**

两端取一颗，得分 = 取完后**剩余所有石子的总和**；Alice 最大化分差、Bob 最小化分差。

```java
// dp[i][j]：区间 [i,j] 当前玩家相对对手的净胜分；prefix 前缀和求区间和
int[][] dp = new int[n][n];
for (int len = 1; len < n; len++) {
    for (int i = 0; i + len < n; i++) {
        int j = i + len;
        dp[i][j] = Math.max(
            sum(i + 1, j) - dp[i + 1][j],   // 取左端，得分 = 剩余总和，对手在 [i+1,j] 的净胜分
            sum(i, j - 1) - dp[i][j - 1]    // 取右端
        );
    }
}
return dp[0][n - 1];
```

要点：得分与"取走的值"无关，而取决于"**剩余多少**"——玩家既要抢先把大石子留给后面（让自己取时剩余更多），又要让对手取时剩余更少。与 486 的唯一差别在"得分来源"。

> 详细解答见：[解题记录/石子游戏VII[1690].md](../../解题记录/石子游戏VII[1690].md)

## 8. 严格证明：为什么 DP 成立（最优子结构与无后效性）

> 这一节回答一个根本问题：凭什么"当前选择会影响后续"，却还能用 DP？答案藏在两条性质里，而这两条性质都源于一个更根本的事实——**双方都最优，会把每个状态的值"钉死"**。

### 8.1 先把博弈形式化

一个完全信息双人零和博弈由以下要素构成：

- 局面集合 S（有限，且任何局面到终局的步数有限）
- 行动集 A(s)：局面 s 下轮到行动的玩家可选的动作
- 转移：选 a 属于 A(s) 后，局面变为 s_a，**当前行动者立即获得收益 r(s,a)**（可为负），然后轮到对手
- 终态：无可行动的局面，记为 t，约定 V(t) = 0（所有收益已在先前的转移中结算完毕）

定义价值函数 V(s)：**在局面 s（轮到玩家 P 行动）时，P 相对对手 Q 的最终净收益（P所得 − Q所得），假设此后双方都各自最大化自己的净收益。**

### 8.2 核心引理：双方最优把值"钉死"（双端夹逼）

对一个子局面 s'（轮到对手 Q 行动），`V(s')` 为什么是一个**确定值**，而不是"取决于 Q 的心情"？因为 Q 会拼尽全力，所以从 Q 的视角同时有：

1. **Q 至少能拿到那么多（可达性，下界）**：Q 存在一个策略，保证自己相对你多拿 >= V(s')
2. **Q 最多只能拿到那么多（最优性，上界）**：无论 Q 怎么走，都无法让自己相对你多拿超过 V(s')

下限和上限重合，于是：**Q 相对你的净收益 = V(s')，不多不少，精确相等。**

这意味着你**不需要猜测 Q 会怎么做**——Q 不会犯傻（不会低于下限），也没有超出上限的超能力。你面对的永远是一个确定数字。这就是整棵博弈树可以被"折叠"成一个数字表的原因。

### 8.3 价值函数的递推式（由此直接推出）

你（P）面对局面 s，考虑行动 a。拿到 r(s,a) 后，局面 s_a 轮到 Q。由 9.2 引理，Q 相对你的净收益**精确等于** V(s_a)。所以：

```
P 相对 Q 的净收益 = r(s,a) - V(s_a)      ← 确定值，无任何不确定性
```

你选对自己最有利的行动，即得递推式：

```
V(s) = max( 对每个可选行动 a ) [ r(s,a) - V(s_a) ]
V(终态) = 0
```

**减号的来源**：V(s_a) 站在对手视角（Q 相对 P），而你要 P 的视角，零和取负即可。同一个 V 同时服务两方，是零和博弈"双方视角互为相反数"的必然结果。

### 8.4 最优子结构的证明

**命题**：V(s) 的最优决策只用到子局面 s_a 的**最优值** V(s_a)，不需要任何其他信息。

**证明**：由 9.2 引理，子局面 s_a 的价值被双方最优**钉死为唯一确定值 V(s_a)**——它不存在"多种可能的更优值"（上限挡住），也不存在"更差但可能发生"（下限保证）。既然子局面的值是唯一的、固定的，父局面用这个固定值就足够了。

反过来说：**如果对手可能失误、可能放水，子局面就会有很多种可能的净胜分，V(s_a) 不是唯一值，最优子结构立刻崩溃。** 所以"双方都最优"这个假设是子结构成立的前提——这正解释了为什么博弈DP只适用于"双方都理性"的零和博弈。

### 8.5 无后效性的证明（数学归纳法）

**命题**：V 的值只由局面本身决定，与到达该局面的历史完全无关。

**基**（终态）：V(t) = 0，与历史无关，成立。

**归纳步**：假设所有"更小"局面的 V 值只由局面决定。由递推式：

```
V(s) = max( a ) [ r(s,a) - V(s_a) ]
```

右边用到的东西：r(s,a)（由当前局面和行动决定）、V(s_a)（由归纳假设，只由 s_a 决定）。**与历史相关的量一个都没出现。** 所以 V(s) 只由 s 决定。证毕。

直观版本：V 的定义是"从该局面**重新开始**一场游戏、双方最优，会得到多少净胜"。这个定义里根本没有"你们之前怎么走到这里的"，所以历史注定影响不了它。

### 8.6 自底向上填表的正确性

- **依赖无环**：递推式里 s_a 比 s "更小"（区间型是区间长度更短，其余类型是剩余步数更少），依赖链严格递减，构成 DAG。
- **无后效性保证值稳定**：每个状态值一旦算出就固定不变，之后不会被修改。
- **最优子结构保证可复用**：大状态直接复用子状态的固定值，不用重算。

于是按"从小到大"（DAG 的拓扑序）填表，每个格子恰好算一次。两条性质缺一不可：缺了无后效性，值会变，复用是错的；缺了最优子结构，光有固定值也拼不出父问题。

### 8.7 与 minimax 的关系（为什么一个函数就够）

经典 minimax 需要**两个**函数，MAX 层求最大、MIN 层求最小：

```
MAX(s) = max( a ) [ r(s,a) + MIN(s_a) ]     // 我方轮次，最大化我方收益
MIN(s) = min( a ) [ r(s,a) + MAX(s_a) ]     // 对方轮次，对方最小化我方收益
```

博弈DP用的 negamax 只用一个 V。二者等价：

> 若把 minimax 的收益统一成"当前行动者 − 对手"（负号视角），MIN 层其实也在**最大化"当前行动者"（即对方）自己的净收益**，而对方净收益 = 我方净收益取负。于是 MAX、MIN 两层套用同一个递推 V(s) = max( a ) [ r(s,a) - V(s_a) ]。边界相同、递推式相同，由归纳唯一性，两者是同一个函数。

一句话：**minimax 的 min 层在 negamax 中变成了"取负后再 max"**。486 的 `Math.max(nums[l] - dp[l+1][r], ...)` 里的 `-` 就是把对手层当成 max 处理的体现。

## 9. 时间复杂度

取决于**局面状态数 × 每局面行动数**：

- 区间型（486/877/1690）：状态数 O(n²)，每状态 2~n 种选择，总 O(n²)~O(n³)，空间 O(n²)
- 带参数型（1140）：状态数 O(n × M)，每状态 O(M) 选择，总 O(n³)，空间 O(n²)
- 前缀取堆型（1406）：状态数 O(n)，每状态 3 种选择，总 O(n)，空间 O(n)
- 取平方数型（1510）：状态数 O(n)，每状态 O(√n) 选择，总 O(n√n)，空间 O(n)
- 分割型（1563）：状态数 O(n²)，每状态 O(n) 分割点，总 O(n³)，空间 O(n²)
- 排序贪心型（1686）：无需 DP，仅 O(n log n) 排序
- 位掩码型（464）：状态数 O(2^m)（m 为可选数字个数），记忆化后每个状态 O(m)
- 图博弈型（913）：状态数 O(V² × 2)（两棋子位置 × 轮到谁）

## 11. 总结口诀

> **零和博弈要记牢：我的优势 = 拿到的 − 对手后续优势**
>
> **状态别存得分，存净胜分，转移永远做减法**
>
> **双方最优值钉死：可达下限封住底，最优上限封住顶，上下相等值唯一**
>
> **区间取数按长度填表，复杂局面记忆化搜索**
>
> **判胜负就看净胜分符号：>= 0 先手不败**
>
> **石子系列形态多：两端取、前缀取、取平方、分割行、双视角贪心——先想清楚"动作形态"再选模板**
