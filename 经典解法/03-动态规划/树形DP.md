# 树形 DP（Tree DP）

## 1. 什么是树形 DP

树形 DP 是**在树结构上做的动态规划**，子问题定义为**以某个节点为根的子树**。

它的核心形态是一句话：**后序遍历递归，把子节点的状态合并成父节点的状态**。因为树天然无环，每个节点在递归中恰好访问一次，子树的子问题互不重叠，所以树形 DP 是"递归 + 状态合并"，**不需要记忆化数组**。

## 2. 适用场景与特征

| 特征 | 说明 |
|------|------|
| **最优子结构** | 整棵树的最优解可以由各子树的最优解合并得到，子树之间互不影响 |
| **无后效性** | 父节点的状态只依赖子节点返回的结果，不关心子树内部"怎么算出来的" |
| **树形依赖** | 父子节点之间存在制约关系（如"选了父就不能选子"），状态转移沿树边传递 |
| **规模大仍可行** | 每个节点只访问一次，合并所有子节点，整体复杂度 O(n) |

典型场景：树上选/不选问题（最大独立集）、树的最长路径（直径）、树上的分配与统计等。

## 3. 核心模板

树形 DP 就是标准的**后序 DFS + 状态合并**：

```java
void dfs(TreeNode node) {
    // 1. 先递归处理所有子节点（自底向上）
    for (TreeNode child : node.children) {
        dfs(child);
    }
    // 2. 递归返回后，用子节点的结果合并出当前节点的状态
    dp[node] = merge(dp[child1], dp[child2], ...);
}
```

| 环节 | 说明 |
|------|------|
| **递归处理子节点** | 必须先算完子树，父节点才能用到子节点的结果 —— 这就是"后序" |
| **合并子节点结果** | 转移方程通常表现为对子节点结果做 `求和 / 取 max / 拼接` 等操作 |
| **叶子边界** | 没有子节点时自然成为递归出口，叶子（或空节点）的 dp 初值即边界 |
| **最终答案** | 一般取根节点的 dp；特殊情况下（如树的直径）需要枚举每个节点 |

**为什么要后序遍历？** 因为 `dp[u]` 只依赖 `dp[子节点]`。子节点必须先算完，父节点才能拿到完整的输入做合并。递归天然保证了"先访问子节点、后处理父节点"的顺序。

## 4. 状态设计原则

状态设计的核心是回答两个问题：

**① dp[u] 表示什么信息？** 通常表示"以 u 为根的子树满足条件的某种最优值 / 方案数 / 其他信息"。

**② 需要几种状态？** 这是树形 DP 最容易出错的地方。当**父节点的决策受"子节点是否被选中"影响**时，只用一个 dp[u] 是不够的，必须为每个节点维护**多个互斥状态**（如"选 u / 不选 u"）。

> 判断标准：如果父节点算答案时需要知道"子节点处于哪种状态"，就必须把这些状态分开记录。
>
> 经典例子（打家劫舍 III）：父节点被偷时，子节点**只能不偷**；父节点不偷时，子节点**可偷可不偷**。所以必须分开记录"偷/不偷"两种状态，父节点才能正确组合。

常见状态形态：

| 问题类型 | 状态设计 |
|----------|----------|
| 树上选/不选 | `dp[u][0]` 不选 u，`dp[u][1]` 选 u |
| 树的最长链 | `dp1[u]` 最长链，`dp2[u]` 次长链（用于拼直径） |
| 路径最大和 | 返回"向下延伸的最大路径和"，再与兄弟链拼接 |

## 5. 经典例题：337. 打家劫舍 III

### 5.1 题目

小偷又发现了一个新的可行窃的地区。这个地区只有一个入口，我们称之为 `root`。除了 `root` 之外，每栋房子有且只有一个"父"房子与之相连。一番侦察之后，聪明的小偷意识到"这个地方的所有房屋的排列类似于一棵二叉树"。

如果**两个直接相连的房子在同一天晚上被打劫**，房屋将自动报警。给定二叉树的 `root`，返回在不触动警报的情况下，小偷能够盗取的最高金额。

> 约束：不能同时偷**直接相连**（父子）的两栋房子。

### 5.2 思路

- **子问题**：以 `node` 为根的子树能盗取的最大金额。
- **状态**：由于"偷了 node，子节点就不能偷"，父节点需要知道子节点被偷与否，所以每个节点维护两个状态：
  - `dp[node][0]`：不偷 node 时，以 node 为根的子树的最高金额
  - `dp[node][1]`：偷 node 时，以 node 为根的子树的最高金额
- **转移**（对左右子节点 l、r）：
  - **偷 node**：左右子节点都不能偷 → `dp[node][1] = node.val + dp[l][0] + dp[r][0]`
  - **不偷 node**：左右子节点各自"偷或不偷都行"，取每边最大值再累加 → `dp[node][0] = max(dp[l][0], dp[l][1]) + max(dp[r][0], dp[r][1])`
- **边界**：空节点偷不偷都是 0 → 返回 `{0, 0}`
- **答案**：根节点两种状态取最大 → `max(dp[root][0], dp[root][1])`

> 关键点：每个子节点**独立决策**，子树各自取最优再累加，这正是最优子结构的体现。

### 5.3 代码（对应 `Algorithm-Cote/src/leetCode/moderately/Rob3.java`）

```java
public class Rob3 {
    public static void main(String[] args) {
        TreeNode root = new TreeNode(2);
        TreeNode node1 = new TreeNode(1);
        TreeNode node2 = new TreeNode(3);
        TreeNode node3 = new TreeNode(4);
        root.left = node1;
        root.right = node2;
        node1.right = node3;
        System.out.println(new Rob3().rob2(root));
    }

    /**
     * 树形 DP 入口
     * 返回根节点"偷/不偷"两种状态的最大值
     */
    public int rob2(TreeNode root) {
        int[] result = dfs2(root);
        // 根节点可取可不取，取两者的最大值
        return Math.max(result[0], result[1]);
    }

    /**
     * 后序 DFS：先算左右子树，再合并出当前节点状态
     *
     * @param node 当前节点
     * @return int[2]：
     *         result[0] = 偷 node 时，以 node 为根的子树最高金额
     *         result[1] = 不偷 node 时，以 node 为根的子树最高金额
     */
    public int[] dfs2(TreeNode node) {
        // 边界：空节点偷与不偷都是 0
        if (node == null) return new int[]{0, 0};

        // 后序：先递归算完左右子树
        int[] leftResult = dfs2(node.left);
        int[] rightResult = dfs2(node.right);

        // 偷 node：左右子节点都不能偷，只能取各自"不偷"状态
        int steal = node.val + leftResult[1] + rightResult[1];
        // 不偷 node：左右子节点偷或不偷都可以，各自取更优再累加
        int notSteal = Math.max(leftResult[0], leftResult[1])
                     + Math.max(rightResult[0], rightResult[1]);

        return new int[]{steal, notSteal};
    }
}
```

复杂度：每个节点只访问一次，合并操作 O(1)，总时间复杂度 **O(n)**，空间复杂度 O(树高)。

## 6. 树形 DP vs 记忆化递归

记忆化递归（top-down DP）与树形 DP 的关系容易混淆，两者的核心区别：

| 对比维度 | 记忆化递归 | 树形 DP |
|----------|-----------|---------|
| **适用对象** | 存在**重叠子问题**的 DP（斐波那契、背包等） | 树结构（子问题天然互不重叠） |
| **缓存** | memo 数组必不可少，防重复计算 | **不需要 memo**，每个节点恰好访问一次 |
| **遍历方向** | 自顶向下拆分 | 后序递归，自底向上合并 |
| **本质** | 一种**实现方式**（top-down） | 一种**问题结构**（状态定义在子树上） |

> **关键认知**：树形 DP 里 memo 是**多余的**。如果发现树形 DP 需要记忆化，通常是把树当成了图（有环），或子问题定义不清晰。树无环 → 无重叠子问题 → 无记忆化。

## 7. 常见变体（独立成篇，此处略）

| 变体 | 一句话描述 | 笔记 |
|------|-----------|------|
| **换根 DP（re-rooting）** | 当答案要求"以每个节点为根"时，一次 DFS 只能算一个根，需要二次 DFS 用父节点信息反推子节点 | 待单独整理 |
| **树形背包** | 子树之间存在"容量竞争"（容量有限，选了子树 A 就不能选 B），dp 状态需增加容量维度，表现为树上分组背包 | 待单独整理 |

## 8. 总结口诀

> **树形 DP 一句话：后序遍历递归，子节点状态合并成父节点状态。**
>
> **状态设计两问题：dp[u] 表示什么？子节点有几种互斥状态？**
>
> **要不要加状态维度：父节点决策依赖子节点"被选与否"时，就必须多维护状态。**
>
> **记忆化是多余的：树无环 → 子问题不重叠 → 不需要 memo。**
