## 使用约定

1. **只追加，不改历史记录**。写错了就新写一条更正，不覆盖前面的内容。
2. 每条记录必须有：日期 + 涉及编号（R01 / N03 / C02 / 专题名）+ 本次做了什么。
3. 掌握度只写「我自我感觉到了哪一步 + 证据」，不写「已掌握」——最终判定回电脑上做。
4. 不在这里重排优先级、不改 P0 名额；只记录依据，回电脑上再决定。
5. 一次记录只对应一个专题，避免一条记录里混多个主题。
6. **日期以写入时设备时间为准**，不套用会话日期、不靠推测；同一天做多道题才共用日期。

### 2026-11-10 [R02] 295 数据流的中位数（对顶堆）

- 本次做了：独立写出 `MedianFinder_295`（大根堆存较小一半 + 小根堆存较大一半）。提交 4/22 挂掉，定位为 `findMedian` 里 `(max.peek() + min.peek()) / 1.0` 的除数写成了 `1.0`，改成 `/ 2.0` 后通过。
- 关键结论：不变量是「大根堆个数比小根堆多 0 或 1」；两堆数量相等取两顶平均，否则取大根堆顶。`addNum` 每次插一个元素，差值最多变化 1，一次 `if / else if` 平衡就够，不需要 `while`。
- 根因：写的时候注意力全在「不能直接 `/2`，会丢精度，要把某个数转成浮点」，结果类型转换写了、除法本身漏了，`/ 1.0` 只完成转型、没做平均。
- 卡点 / 薄弱点：
  1. 口述思路时说「保证小根堆数量大于大根堆」，与实现的「大根堆多 0 或 1」方向相反，不变量没固化。
  2. 测试分支覆盖不全：前 4 个用例都是奇数个元素，走 `return max.peek()` 分支，平均分支一次都没被执行。
- 证据：239 与 295 均通过；能说出两种堆划分方向各自的取中位数公式；复杂度 `addNum` O(log n)、`findMedian` O(1)。
- 待回填：`学习计划.md` R02 → 已完成；`掌握度与薄弱点.md` 7.2 证据补「295 对顶堆」，状态维持「熟悉」不升级。
- 校验教训：对拍必须逐字转写待测代码，不能按「应该怎么写」重写。本次 2 万组对拍全绿但实际提交失败，就是因为转写时把 `/ 1.0` 自动补成了 `/ 2.0`，等于把 bug 抹掉了。

### 2026-11-11 [R06] 39 组合总和（回溯枚举，未闭环）

- 本次做了：先用完全背包 DP 求组合，意识到题目要明细不是数量后改写 dfs；按「每种元素取几个」范式写出初版，有 3 处 bug，修正后通过（3000 组随机对拍 + 手算边界）。
- 关键结论：输出是全部具体组合，规模随 target 指数增长，只能靠搜索枚举；DP 把方案压缩成计数，不可逆。两种范式二选一：按元素决策「每种取几个」（不需要 start），或按位置推进（start 传 `i` 表示可重复用，传 `i+1` 表示不可重复）。
- 卡点 / 薄弱点：
  1. 把「外层从 0 开始枚举」当成求排列的原因，实际原因是「下标可以往回走」，与 DP 的外层循环无关。结论对、理由错。
  2. 把 `subList(...)` 当成删除操作，忘了它只是视图，必须 `.clear()`。
  3. 回溯计数错位：循环里加了 `i-1` 个却按 `i` 个删，`[2], target=2` 直接下标越界。
  4. 终止条件顺序：`index == length` 放在 `target == 0` 前面，最后一个元素刚好凑满时漏解。
- 证据：修正版对拍 3000 组无差异；`[2],2`、`[2],4`、`[2,3],5`、`[2,3,6,7],7` 手算一致。
- 待回填：`学习计划.md` R06 → 进行中（39 在提示后修正，非一次性独立通过；46 未做）；`掌握度与薄弱点.md` 8.4 证据补「39 三处回溯 bug」，状态维持「熟悉」不升级。

### 2026-11-12 [新学] 40 组合总和 II（按值分组枚举，与 39 的分水岭）

- 本次做了：套用 39 的「取 / 不取」二叉决策写初版，输出重复解；改为「按值分组枚举个数」后通过（5000 组随机对拍 + 四个边界样例）。
- **与 39 的关键差异（初版写错的根本原因）**：
  1. 39 题面保证候选数**互不相同**，所以二叉树上「第 i 个下标取或不取」唯一对应一个决策，同一组合只可能由一条路径产出，天然无重复。
  2. 40 允许候选数**重复**。「用第 0 个 1」和「用第 1 个 1」是两条不同的路径，但产出的组合完全一样——重复不是递归结构写错，而是「相同值的不同副本」在下标层面天然存在二义性。
  3. 所以 39 的骨架可以照抄，但**去重逻辑必须新增**，不能指望它自己正确。
- 解法定型：每层取一个同值段 `[index, end)`，枚举取 `k = 0..cnt` 个，递归到 `end`（跳过整段相同值）；`k` 同时表示「本轮已放进路径的个数」和「下一轮要递归的状态」，循环内先递归再 add，退出时删 `k` 个。
- 两种等价写法：①按值分组枚举个数（本次采用，与 39 那版同构）；②标准 `for + continue`，`i > start && nums[i] == nums[i-1]` 同层去重，面试更常见。
- 关键边界：`[1,1,1,1], 2 → [[1,1]]`；最小值已超 target（第一层剪枝直接空）；单元素刚好等于 target。
- 已修的两处隐患：`target == 0` 后补 `return`（原来靠 `curVal > target` 兜底，遇到 0 元素会重复收集）；`removeLast()` 改成 `subList(...).clear()`，不再依赖 Java 21。
- 待回填：`掌握度与薄弱点.md` 8.4 证据补「40 按值分组枚举 + 与 39 的差异」，状态维持「熟悉」；`学习计划.md` 需给 40 找落点；R06 完成标准需修订。

### 2026-11-13 [R06] 46 全排列（used 数组）

- 本次做了：独立写出 `Permute_46`，`used[]` 按按下标标记，for 循环枚举未使用的下标；n = 1~6 与 `itertools.permutations` 对拍完全一致（1/2/6/24/120/720）。
- 关键结论：`used` 标记的是**下标**而不是值——全排列允许元素出现在任意位置，只禁止同一个位置被重复使用。回溯返回前要还原三类东西：①路径（`curNodes` 里加的元素）②状态标记（`used[i]`、`visited[][]`、棋盘落子）③参数（`target - x` 这类值传递，自动还原，不用手写）。
- **39 / 40 / 46 判据对照**：

  | 题 | 值可否重复 | 同一元素可否重复用 | 顺序是否重要 | 判据 |

  | 40 | 可重复 | 不可以 | 组合，不重要 | 排序 + 同层跳过同值 |
  | 46 | 不可重复 | 不可以 | 排列，重要 | `used[]` 按下标标记 |

  选范式只问两句：顺序重不重要？同一元素能不能反复用？
