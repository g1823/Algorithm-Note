# 延迟删除（懒惰删除，Lazy Deletion）

## 问题背景

`PriorityQueue`（堆）支持 O(1) 取最值、O(log n) 插入，但**不支持 O(log n) 删除任意元素**。`remove(O)` 是 O(n) 线性扫描。

当需要在堆中删除非堆顶元素时（如滑动窗口离开、扫描线中建筑结束），如果直接调用 `remove`，总体复杂度会退化到 O(n²)。

## 核心思路

用 HashMap 记录"待删除元素"及其次数，**不立即从堆中移除**，而是等到该元素出现在堆顶时才真正弹出（prune）。

```
删除时  → map[element]++（标记待删）
取堆顶时 → while(堆顶在 map 中) { poll(); 更新计数 }
```

## 两种典型变体

### 变体一：单堆模型（218. 天际线问题）

场景：只需要**维护当前最大值**，旧元素过期时需要移除。

```java
Map<Integer, Integer> pending = new HashMap<>();   // 待删计数
PriorityQueue<Integer> pq = new PriorityQueue<>(Comparator.reverseOrder());

// 加元素
pq.add(height);

// 删元素（标记而已）
pending.put(height, pending.getOrDefault(height, 0) + 1);

// 取最大值前，先清理堆顶的"已过期"元素
while (!pq.isEmpty() && pending.getOrDefault(pq.peek(), 0) > 0) {
    int h = pq.poll();
    pending.put(h, pending.get(h) - 1);
    if (pending.get(h) == 0) pending.remove(h);
}
int max = pq.isEmpty() ? 0 : pq.peek();
```

**特点**：只需要一个堆 + 一个 map，prune 时机固定（每次取 max 前）。

### 变体二：双堆模型（480. 滑动窗口中位数）

场景：需要**同时维护两个堆的平衡**（大顶堆存小半、小顶堆存大半），元素跨堆移动时，被动删除的目标堆中可能残留已标记项。

```java
// 删除标记（无需区分属于哪个堆，统一标记）
map.put(num, map.getOrDefault(num, 0) + 1);

// 逻辑 size 手动维护——这是双堆模型的关键
if (num <= maxHeap.peek()) maxSize--;
else minSize--;

// 每次堆顶变动后都 prune
prune(maxHeap);
prune(minHeap);
rebalance();

// prune 方法（两个堆共用同一张 map）
void prune(PriorityQueue<Integer> heap) {
    while (!heap.isEmpty() && map.containsKey(heap.peek())) {
        int num = heap.poll();
        map.put(num, map.get(num) - 1);
        if (map.get(num) == 0) map.remove(num);
    }
}
```

**特点**：
- 两个堆共享同一张删除 map（元素在哪个堆不重要，只问"是否被标记删除"）
- 需要手动维护**逻辑 size**（`maxSize`/`minSize`），因为 `heap.size()` 不再反映真实元素数
- prune 时机更多：每次删除后、每次 rebalance 从对方堆取元素后

## 模板

```java
class LazyDeletionHeap {
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    Map<Integer, Integer> pending = new HashMap<>();

    void add(int val) {
        heap.offer(val);
    }

    void remove(int val) {
        pending.put(val, pending.getOrDefault(val, 0) + 1);
        prune();  // 如果想立即清理，否则在 peek/poll 前调
    }

    int peek() {
        prune();
        return heap.isEmpty() ? defaultVal : heap.peek();
    }

    int poll() {
        prune();
        return heap.poll();
    }

    private void prune() {
        while (!heap.isEmpty() && pending.getOrDefault(heap.peek(), 0) > 0) {
            int val = heap.poll();
            pending.put(val, pending.get(val) - 1);
            if (pending.get(val) == 0) pending.remove(val);
        }
    }

    boolean isEmpty() {
        prune();
        return heap.isEmpty();
    }
}
```

## 注意事项

1. **计数而非布尔**：同值元素可能出现多次，用 `int` 计数，不用 `boolean`
2. **prune 只清理堆顶**：堆中部的被标记元素不主动删除，等它们自然上浮到堆顶再清理
3. **双堆模型的逻辑 size**：`heap.size()` 含已标记的垃圾元素，必须单独维护一个 `logicalSize`
4. **prune 的触发点**：单堆只需 peek/poll 前 prune；双堆需要在每次删除和跨堆移动后 prune

## 复杂度

- 每个元素入堆一次、出堆最多一次，均摊 O(log n)
- 删除操作 O(1)（仅 map 操作）

## 应用题目

| 题目 | 模型 | 说明 |
|:----:|:----:|------|
| 218. 天际线问题 | 单堆 | 最大堆 + 延迟删除，事件离开时标记 |
| 480. 滑动窗口中位数 | 双堆 | 双堆 + 逻辑 size + 延迟删除，窗口滑动时元素离开 |
| 239. 滑动窗口最大值 | 单堆（可替代单调队列） | 最大堆 + 延迟删除，窗口滑动时移出旧元素 |
